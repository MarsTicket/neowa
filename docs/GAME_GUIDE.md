## 0. 품질 기준

이전 버전은 사이트 주인이 **"너무 형편없다"** 고 판단해서 전부 갈아엎었습니다. 그때 문제였던 점과 지금 기준은 이렇습니다.

| 예전 문제 | 지금 기준 |
|---|---|
| 관리자 화면 같은 밋밋한 카드 목록 | 게임 사이트다운 강한 첫인상 (네온, 큰 제목, 움직이는 배경) |
| 모바일에서 게임판이 화면의 1/3 | **게임판이 화면을 최대한 꽉 채움**. 점수는 게임판 위에 얇게 겹쳐 표시 (HUD) |
| 점수 카드와 버튼이 게임보다 큼 | 버튼은 상단 바의 아이콘 3개(소리·전체화면·일시정지)뿐 |
| 효과 없음 | 폭발 파티클, 화면 흔들림, 점수 글자, 효과음, 진동이 기본 |
| 끝나면 그냥 끝 | 종료 화면에 점수 올라가는 효과, 신기록 배지, **다음 게임 추천** |
| 키보드 전제 | **터치만으로 완주 가능**해야 함 (휴대폰, 테슬라 차량 화면) |

**새 게임도 위 기준을 모두 지켜야 합니다.** 견본(`_template/`)을 복사해서 시작하면 대부분 자동으로 맞춰집니다.

게임 자체의 재미 기준:
- 시작 3초 안에 무엇을 해야 하는지 알 수 있어야 함 (시작 화면 설명은 2문장 이내)
- 한 판 1~5분. 실패해도 바로 "다시 하기"
- 점점 어려워지는 장치 (레벨, 웨이브, 속도 증가)
- 점수를 더 얻는 욕심 요소 (콤보 배율, 황금 아이템, 보스)
- **기존 유명 게임을 그대로 베끼지 말 것.** 장르(슈팅, 퍼즐 등)는 괜찮지만 특정 게임의 이름·캐릭터·레벨 디자인을 복제하면 안 됩니다.

## 1. 사이트 구조 한눈에 보기

```
neowa/
├─ index.html              ← 메인(허브) 페이지. 게임 카드, 스토리 배너

├─ snake/index.html        ← 게임 02 네온 스네이크
├─ breakout/index.html     ← 게임 03 네온 브레이커 (벽돌깨기)
├─ story/index.html        ← 비주얼노벨 "방과 후, 너와" (별도 엔진, 이 지침 대상 아님)
├─ _template/index.html    ← ★ 새 게임 견본 (별 줍기). 이걸 복사해서 시작
│                             (밑줄로 시작하는 폴더라 GitHub Pages에 공개되지 않음)
├─ about / characters / contact / privacy .html  ← 스토리 게임용 문서 페이지
├─ assets/
│  ├─ arcade/arcade.js     ← ★ 게임 공통 엔진 (저장, 사운드, 이펙트, 화면 상태, 크기 맞춤)
│  ├─ arcade/arcade.css    ← ★ 게임 공통 디자인
│  ├─ <id>-card.jpg        ← 게임 카드 그림 (shooting-card.jpg 등)
│  ├─ engine.js, scenario.js, style.css, i18n/, images/  ← 스토리 게임 전용 (건드리지 말 것)
│  └─ three.min.js, sounds/ ← 예전 버전 잔재. 지금은 안 씀
├─ docs/GAME_GUIDE.md      ← 이 문서
├─ docs/tools/smoke.js     ← 자동 점검 스크립트

```

- **서버 없음.** GitHub Pages로 올라가는 정적 사이트입니다. 빌드 과정도, npm 패키지도 없습니다. HTML 파일 하나에 게임 코드를 다 넣습니다.
- 견본을 브라우저로 보려면 내 컴퓨터에서 `python3 -m http.server 8765` 후 `http://localhost:8765/_template/` 로 엽니다.
- 도메인: `neowa.kr` (CNAME 파일). 파일을 `main` 브랜치에 병합하면 몇 분 뒤 사이트에 반영됩니다.

## 2. 새 게임 만들기: 10단계 요약

예시: "점프"라는 게임을 `jump`라는 영문 id로 추가하는 경우

1. **id 정하기**: 영문 소문자 한 단어 (`jump`). 폴더 이름 = id = 저장 키 이름에 모두 쓰입니다.
2. **폴더 복사**: `_template/` → `jump/` (`jump/index.html`)
3. **TODO 고치기**: `jump/index.html` 안에서 `TODO`를 검색해 전부 바꿉니다.
   - `<meta name="robots" content="noindex">` 줄 **삭제** (견본만 검색에서 숨김)
   - 제목, 설명, og 태그, 대표색(`--accent`, `--accent-ink`, `--ar` 세 개 함께), STAGE 번호
   - `new A.Shell({ id: 'jump', ... })` ← 폴더 이름과 똑같이
4. **게임 로직 작성**: `reset / update / render` 세 함수를 채웁니다 (4장).
5. **조작 작성**: 터치·마우스·키보드 모두 (5장). 키보드 없이 터치만으로 끝까지 할 수 있어야 합니다.
6. **카드 그림 만들기**: `assets/jump-card.jpg` (7장 이미지 규격). 파일 이름은 반드시 `<id>-card.jpg`. 메인 페이지 "최근 플레이"가 이 이름 규칙으로 그림을 찾습니다.
7. **메인 페이지에 카드 추가** (6장)
8. **다른 게임과 연결**: 종료 화면 "다음 게임", 옆 패널 "MORE GAMES" (6장)
9. **sitemap.xml에 주소 추가**: `<url><loc>https://neowa.kr/jump/</loc></url>`
10. **점검 후 PR** (10장, 11장)

## 3. 게임 페이지 HTML 규칙

견본 파일을 그대로 쓰면 아래 규칙이 이미 지켜져 있습니다. **id 이름은 엔진이 찾아 쓰므로 바꾸면 안 됩니다.**

### 3-1. 고정 id 목록

| id | 역할 | 필수 |
|---|---|---|
| `wrap` | 무대를 감싸는 영역. 엔진이 크기를 재서 게임판 크기를 정함 | 필수 |
| `stage` | 게임판 테두리. 터치 입력을 여기에 붙임 | 필수 |
| `cv` | 캔버스 | 필수 |
| `ovStart` | 시작 화면. 아무 데나 누르면 시작 | 필수 |
| `ovPause` | 일시정지 화면 | 필수 |
| `ovOver` | 종료 화면 | 필수 |
| `ovScore` | 종료 화면의 큰 점수 (엔진이 숫자 올라가는 효과로 채움) | 필수 |
| `ovNew` | "NEW RECORD" 배지 (엔진이 보이기/숨기기) | 필수 |
| `ovMeta` | 종료 화면의 작은 통계 3개 (엔진이 채움) | 선택 |
| `banner` | 화면 가운데 "WAVE 2" 같은 알림 | 선택 |

### 3-2. 엔진이 자동으로 처리하는 속성

| 속성 | 하는 일 |
|---|---|
| `data-act="start"` / `"restart"` | 누르면 게임 시작(처음부터) |
| `data-act="resume"` | 일시정지 풀기 |
| `data-act="pause"` | 일시정지 |
| `data-act="mute"` | 소리 켜기/끄기 (켜짐/꺼짐 아이콘 `.on`/`.off`) |
| `data-act="fs"` | 전체 화면 (지원 안 하는 브라우저에선 자동으로 숨김) |
| `data-best` | 안의 글자를 최고기록 숫자로 채움 |
| `data-plays` | 안의 글자를 플레이 횟수로 채움 |

### 3-3. 화면 상태 (body의 `data-state`)

엔진이 `<body data-state="...">`를 바꾸면 CSS가 알아서 화면을 바꿉니다.

```
ready (시작 화면) ──시작──▶ playing ──P/Esc/버튼──▶ paused ──계속──▶ playing
                              │
                              └──S.gameOver()──▶ over (종료 화면) ──다시 하기──▶ playing
```
- 다른 탭으로 가거나 창이 포커스를 잃으면 **자동 일시정지**.
- HUD(`.g-hud`)는 playing / paused 상태에서만 보입니다.

### 3-4. 기기별로 다른 문구 보여 주기

- `class="k-only"`: 키보드·마우스 기기에서만 보임 (예: "←→ 이동", "P 일시정지")
- `class="t-only"`: 터치 기기(휴대폰·태블릿·테슬라)에서만 보임 (예: "화면을 끌면 이동")
- 엔진이 터치 기기를 알아내면 `<body>`에 `touch` 클래스를 붙입니다. CSS에서 `.touch .내클래스{}`로 터치 전용 스타일을 줄 수 있습니다.

### 3-5. 방향 패드가 필요한 게임

스네이크처럼 상하좌우 버튼이 필요하면 `snake/index.html`의 `<div class="g-pad">...</div>` 블록을 그대로 복사해 견본의 맨 아래 빈 `<div></div>` 자리에 넣으세요.
- 세로 화면: 게임판 아래에 버튼 4개
- 가로 터치 화면(테슬라 등): 엔진이 자동으로 게임판 오른쪽에 큰 십자 모양으로 옮기고, 그만큼 게임판 크기를 줄여 겹치지 않게 합니다.
- 버튼 눌림 처리는 `snake/index.html`의 `.pad [data-dir]` 부분 코드를 참고하세요.

## 4. 공통 엔진 `arcade.js` 사용법

페이지에서 `<script src="../assets/arcade/arcade.js?v=2"></script>`로 불러오면 `window.Arcade`(보통 `var A = Arcade;`)가 생깁니다.

### 4-1. Shell: 게임의 틀

```js
var S = new A.Shell({
  id: 'jump',          // 폴더 이름. 저장 키: neowa_hub_jump_high, neowa_plays_jump
  W: 540, H: 960,      // 논리 해상도 (아래 설명)
  init:   function () {},          // 선택. 페이지 열릴 때 1번 (시작 화면 뒤 장식용 상태 준비)
  reset:  function () {},          // 필수. 시작/다시 하기 때마다. 모든 변수를 처음 값으로
  update: function (dt) {},        // 필수. playing 상태에서 매 프레임. dt = 초 (최대 0.033)
  idle:   function (dt) {},        // 선택. playing이 아닐 때 매 프레임 (보통 fx.update(dt)만)
  render: function (ctx, dt) {},   // 필수. 상태와 상관없이 매 프레임
  keydown: function (e) {},        // 선택. playing 중 키 누름
  keyup:   function (e) {},        // 선택
  onResize: function () {}         // 선택. 화면 크기가 바뀐 뒤
});
```

**논리 해상도 (W, H)**: 화면이 휴대폰이든 테슬라든 게임 코드는 항상 `W x H` 좌표로 그립니다. 엔진이 실제 화면 크기와 선명도(레티나)에 맞춰 자동 확대·축소합니다.
- 세로형 게임 권장: `540 x 960` (슈팅, 벽돌깨기, 견본)
- 정사각형에 가까운 게임: 스네이크는 `600 x 720` (위쪽 60은 HUD 자리)
- 가로형도 가능(`960 x 540`)하지만 휴대폰 세로 화면에서 작아지므로 신중히.
- **HUD가 위쪽 약 60~70px을 덮습니다.** 중요한 물체를 맨 위에 두지 마세요.

**Shell이 주는 것**

| 이름 | 설명 |
|---|---|
| `S.state` | `'ready'`, `'playing'`, `'paused'`, `'over'` |
| `S.time` | 페이지가 열린 뒤 흐른 초 (깜빡임·흔들림 애니메이션용) |
| `S.best` | 현재 최고기록 |
| `S.gameOver(score, meta)` | 게임 종료. `meta` = `[['웨이브','5'], ['격추','120']]` 식으로 최대 3개 |
| `S.banner('WAVE 3', 'GET READY')` | 화면 가운데 큰 알림 (큰 글자, 작은 글자) |
| `S.toLocal(e)` | 터치/마우스 이벤트 좌표 → 논리 좌표 `{x, y}` |
| `S.start()`, `S.pause()`, `S.resume()` | 직접 호출할 일은 드묾 (버튼·키가 알아서 부름) |

**엔진이 이미 쓰는 키 (게임에서 다른 용도로 쓰지 말 것)**: `Space`/`Enter`(시작·재개·재시작), `P`/`Esc`(일시정지), `M`(소리), `F`(전체 화면), `R`(종료 화면에서 다시 하기). 단, `Space`는 playing 중에는 게임의 `keydown`으로 전달되므로 "발사" 등에 써도 됩니다(벽돌깨기 참고).

**죽는 연출 규칙**: 목숨이 0이 되는 순간 바로 `S.gameOver()`를 부르지 말고, 1초 정도 폭발 연출을 보여 준 뒤 부르세요. 견본의 `dyingT` 방식을 따르면 됩니다.

### 4-2. FX: 이펙트

```js
var fx = new A.FX();
// update 안에서:  fx.update(dt);
// render 안에서:  var o = fx.offset(); c.save(); c.translate(o[0], o[1]); ...그리기... fx.draw(c); c.restore(); fx.drawFlash(c, W, H);
```

| 함수 | 쓰임 |
|---|---|
| `fx.burst(x, y, '#ff5d8f', 개수, 속도, 수명초, 크기)` | 폭발 파티클. 보통 `(x, y, 색, 20, 300, 0.6, 3)` |
| `fx.spark(x, y, 색, vx, vy, 수명, 크기)` | 파티클 1개 (엔진 불꽃, 꼬리 등) |
| `fx.ring(x, y, 색, 반지름, 수명)` | 퍼져 나가는 원 (충격파) |
| `fx.text(x, y, '+100', 색, 글자크기)` | 떠오르는 점수 글자 |
| `fx.shake(세기, 시간)` | 화면 흔들림. 작은 타격 `(2, 0.1)`, 피격 `(10, 0.4)`, 보스 `(14, 1)` |
| `fx.flashIt(색, 세기)` | 화면 전체 번쩍임. 피격 `('#ff2244', 0.6)` |
| `fx.clear()` | 전부 지우기 (reset에서 호출) |

### 4-3. 사운드: `A.sfx('이름', 음높이배율)`

음악 파일 없이 브라우저가 즉석에서 소리를 만듭니다. 쓸 수 있는 이름:

| 이름 | 어울리는 곳 |
|---|---|
| `shoot` | 총알 발사 (아주 작은 소리, 자동 연사용) |
| `hit` | 맞았지만 안 부서짐 |
| `boom` / `bigboom` | 작은 폭발 / 큰 폭발·보스 |
| `hurt` | 내가 피격 |
| `power` | 아이템 획득 |
| `coin`, `eat`, `gold` | 점수 획득 / 먹기 / 특별 보상 |
| `bounce`, `wall` | 튕김 / 벽 부딪힘 |
| `brick`, `steel` | 블록 깨짐 / 단단한 것 |
| `turn`, `tick`, `click` | 방향 전환 / 째깍 / 버튼 |
| `start`, `level`, `over`, `record` | 시작 / 레벨업 / 게임오버 / 신기록 (엔진이 start·over·record는 자동 재생) |

- 두 번째 값으로 음높이를 바꿀 수 있습니다: `A.sfx('brick', 1 + combo * 0.06)` → 콤보가 쌓일수록 높아지는 소리.
- 같은 소리를 0.03초 안에 여러 번 부르면 한 번만 납니다(겹침 방지). 새 소리가 필요하면 `arcade.js`의 `SFX` 표에 추가하세요.
- 진동: `A.vibrate(150)` 또는 `A.vibrate([15, 30, 15])` (지원 기기만)

### 4-4. 그리기 도우미

| 함수 | 설명 |
|---|---|
| `A.sprite('키', w, h, function (x, w, h) {...})` | 그림을 미리 한 번만 그려 저장(캐시). **빛 번짐(shadowBlur)은 반드시 여기서만** |
| `A.draw(ctx, sprite, x, y, 배율, 회전)` | 저장한 그림을 **가운데 기준**으로 그리기 |
| `A.glowDot('#ffd166', 반지름)` | 빛나는 점 그림 (총알, 먹이, 파티클) |
| `A.rr(ctx, x, y, w, h, r)` | 둥근 사각형 경로 (그 뒤 `fill()`/`stroke()`) |
| `A.hexA('#ff5d8f', 0.5)` | 색에 투명도 붙이기 → `rgba(...)` |

빛나는 물체는 `ctx.globalCompositeOperation = 'lighter'`로 겹쳐 그리면 네온 느낌이 납니다(슈팅의 총알, 파티클 참고).

### 4-5. 숫자·저장 도우미

| 함수 | 설명 |
|---|---|
| `A.rand(a, b)`, `A.irand(a, b)` | 실수/정수 난수 |
| `A.clamp(v, a, b)`, `A.lerp(a, b, t)`, `A.pick(배열)` | 범위 제한, 보간, 무작위 선택 |
| `A.fmt(12345)` → `"12,345"` | 점수 표시 |
| `A.get(k, 기본값)`, `A.set(k, v)`, `A.getInt(k)` | localStorage (오류 나도 안전) |

### 4-6. 저장 키 규칙 (바꾸면 기존 기록이 사라짐)

## 5. 조작(입력) 만드는 법

**원칙: 같은 게임을 ① 휴대폰 터치 ② PC 키보드·마우스 ③ 테슬라 터치 화면에서 모두 끝까지 할 수 있어야 합니다.**

입력은 `pointerdown / pointermove / pointerup` (포인터 이벤트)로 만듭니다. 마우스와 터치를 한 번에 처리합니다. `touchstart`나 `mousedown`을 따로 쓰지 마세요.

### 패턴 A. 상대 드래그 (슈팅, 벽돌깨기, 견본)
손가락이 캐릭터를 가리지 않도록, **누른 곳에서 움직인 거리만큼만** 캐릭터를 움직입니다. 터치는 1.25~1.3배 민감하게.
→ 견본 `_template/index.html`의 8번 코드 그대로 사용.

### 패턴 B. 스와이프 (스네이크)
22px 이상 밀면 방향 전환, 손을 떼지 않아도 연속 스와이프 가능. 방향 입력은 최대 3개까지 줄 세워(큐) 빠른 연타도 놓치지 않게.
→ `snake/index.html`의 `turn()`과 `pointermove` 코드 참고.

### 패턴 C. 짧은 탭 = 행동 (벽돌깨기 공 발사)
누른 뒤 12px 미만으로 움직이고 0.35초 안에 떼면 "탭". 드래그와 구분됩니다.
→ `breakout/index.html`의 `pointerup` 코드 참고. **탭을 안 해도 3초 뒤 자동 발사**처럼 막힘 방지 장치를 꼭 넣으세요.

### 키보드
- 방향키 + WASD 둘 다 지원. `keys` 객체에 눌림 상태를 저장해 `update`에서 읽습니다(견본 참고).
- 키 이름 정리: `e.key.length === 1 ? e.key.toLowerCase() : e.key` (대문자 A와 a를 같게)

### 시작 방법
엔진이 처리합니다: 시작 화면 아무 데나 탭 / 스페이스 / 엔터. 따로 만들 필요 없습니다.

## 8. 테슬라·구형 브라우저 호환 규칙

이 사이트는 **테슬라 차량 브라우저**에서도 쓰입니다. 테슬라 브라우저는 키보드가 없는 터치 전용 가로 화면(대략 1180x720 ~ 1600x900)이고, 일반 크롬보다 **버전이 늦을 수 있습니다**(크로미움 100번대 가정).

### 엔진이 이미 해 주는 것
- 터치 기기·테슬라 자동 판별 → `body.touch` 클래스, 키보드 안내 숨김, 버튼 확대
- 가로 터치 화면에서 방향 패드를 게임판 오른쪽으로 이동
- 넓은 화면에서 게임판 양옆에 조작법·기록 패널
- 메인 페이지: 테슬라로 접속하면 "주차(P) 상태에서만 즐겨 주세요" 안내

### 새 코드에서 지켜야 할 것 (최신 기능 금지 목록)

| 쓰지 말 것 | 대신 쓸 것 | 이유 |
|---|---|---|
| CSS `color-mix()` | `rgba(var(--ar), .3)` | 크롬 111 이상만 지원 |
| CSS `inset: 0` | `top:0;right:0;bottom:0;left:0` | 크롬 87 이상 |
| CSS `cqw`, `dvh` 단위 단독 사용 | 앞에 일반 값 한 줄 먼저: `font-size:44px;font-size:clamp(34px,11cqw,58px)` | 지원 안 하면 앞 줄이 쓰임 |
| CSS `:has()` | 클래스로 처리 | 크롬 105 이상 |
| `aspect-ratio` 단독 | `@supports not (aspect-ratio:1/1){...}`에 높이 대체값 | 크롬 88 이상 |
| 캔버스 `ctx.filter` | 같은 그림을 `'lighter'`로 한 번 더 그리기 | 사파리(아이폰) 미지원 |
| 캔버스 `ctx.roundRect()` | `A.rr()` | 구형 미지원 |
| JS `?.`, `??`, `Array.at()`, `structuredClone` | 일반 문법 | 구형 미지원 |
| 매 프레임 `shadowBlur` | `A.sprite()`로 미리 그리기 | 테슬라 구형 칩에서 매우 느림 |

- 화면 비율은 테슬라 가로 화면에서 확인하세요(10장 점검 스크립트가 자동으로 찍어 줍니다).
- 테슬라는 진동이 없고, 전체 화면 기능 지원 여부가 확실하지 않습니다. 둘 다 **없어도 게임이 문제없이 돌아가게** 만드세요.

## 9. 절대 하지 말 것 / 자주 하는 실수

**절대 하지 말 것**
1. 게임 페이지에 **애드센스 광고 스크립트를 넣지 말 것.** 자동 광고가 게임판 위에 떠서 조작을 방해합니다. 광고는 메인·문서 페이지에만 있습니다. (구글 애널리틱스 `gtag`는 게임 페이지에도 넣음)
2. 저장 키 이름(4-6) 바꾸지 말 것. 사용자 기록이 사라집니다.
3. `story/`와 스토리 전용 파일(`assets/engine.js`, `scenario.js`, `style.css`, `i18n/`, `images/`)은 이 작업과 무관합니다. 건드리지 말 것.
4. 공통 엔진(`arcade.js`, `arcade.css`)을 고칠 때는 **기존 게임 3개가 다 정상인지** 점검 스크립트로 확인할 것. 고친 뒤에는 모든 게임 HTML의 `?v=2`를 `?v=3`처럼 올려야 방문자 브라우저가 옛 파일을 계속 쓰지 않습니다.
5. 외부 라이브러리(three.js 등)나 빌드 도구를 새로 들이지 말 것. 지금 구조(HTML 한 파일 + 공통 엔진)를 유지합니다.
6. `main` 브랜치에 직접 올리거나 PR을 직접 병합하지 말 것. 병합은 사이트 주인이 결정합니다.

**자주 하는 실수**
- `var S = new A.Shell(...)`는 맨 아래에 있습니다. 위쪽 함수에서 `S`를 쓰는 건 괜찮지만, **`init` 안에서는 `S`를 쓰면 안 됩니다** (아직 만들어지는 중).
- `render`는 시작 전에도 불립니다. 게임 변수가 아직 없을 수 있으니 `if (!player) return;` 같은 보호 코드를 넣으세요.
- `update`에서 매 프레임 `innerHTML`로 HUD를 다시 쓰면 느려집니다. 값이 바뀔 때만 갱신하세요(견본의 `lastHud`).
- 배열을 돌면서 지울 때는 **뒤에서부터** (`for (i = arr.length - 1; i >= 0; i--)`).
- 빠른 물체(공, 총알)는 한 프레임에 크게 움직여 벽을 뚫습니다. 벽돌깨기처럼 **잘게 나눠 여러 번 이동(서브스텝)** 하세요.
- 시간 기준으로 움직이세요(`x += 속도 * dt`). 프레임 수 기준으로 움직이면 기기마다 속도가 달라집니다.
- 게임이 너무 어렵거나 막히는 상황(공이 수평으로 끝없이 왕복 등)을 막는 보정 장치를 넣으세요.

## 12. 부록: 기존 게임 3종 구조 요약

새 게임을 만들 때 비슷한 기능이 있으면 아래 파일에서 해당 부분을 가져다 쓰세요.

### 별빛 수호대 `shooting/` (540x960, 하늘색)
- 상대 드래그 이동 + 자동 연사(0.11초)
- 적 5종: drone(직진), weaver(사인파), gunner(멈춰서 조준 사격), tank(체력 많음, 아이템 확정), boss(5웨이브마다, 탄막 패턴 3종, 체력 40% 이하 분노)
- 웨이브 구성: `buildWave(n)`이 패턴(line, vee, column, rain, gunners, tank)을 예산만큼 뽑아 시간표(queue) 생성 → **레벨 디자인 자동 생성 예시**
- 아이템: P(화력 1→5), S(보호막), ♥(목숨). 가까이 가면 자석처럼 끌려옴
- 콤보: 1.6초 안에 연속 격추 → 6마리마다 배율 +1 (최대 ×8)
- 피격 시 2.2초 무적 깜빡임, 화력 1단계 감소

### 네온 스네이크 `snake/` (600x720, 연두)
- 칸(20x22) 기반, 틱마다 한 칸 이동. 칸 사이를 **보간**해서 부드럽게 그림 (`prev` 배열)
- 벽 통과(반대편으로), 내 몸·바위에 닿으면 끝
- 먹이 6개마다 레벨업(속도 증가), 레벨 3부터 바위 2개씩 추가
- 먹이 5개마다 황금 먹이(6초 제한, 남은 시간만큼 추가 점수)
- 입력 큐(최대 3), 스와이프 + 방향 패드
- 죽을 때 머리부터 마디가 하나씩 터지는 연출

### 네온 브레이커 `breakout/` (540x960, 주황)
- 레벨을 **글자 지도**로 정의 (`LEVELS` 배열): `.` 빈칸, `1~3` 내구도, `#` 강철, `*` 아이템 확정
- 8스테이지 후에는 처음부터 내구도 +1로 반복 (HARD MODE)
- 공은 서브스텝(5px 단위)으로 이동해 뚫림 방지, 패들 맞은 위치로 반사 각도 결정
- 아이템 5종: W(패들 확장 12초), M(공 +2), F(관통 불꽃공 8초), S(감속 9초), ♥(목숨)
- 공이 패들에 붙어 있으면 탭/스페이스로 발사, 3초 지나면 자동 발사
- 벽돌이 스테이지 시작 때 순서대로 나타나는 연출(`born`)
