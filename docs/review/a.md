# 게임 보완 기획서 — 묶음 a

대상: 별빛 수호대(shooting), 네온 스네이크(snake), 네온 브레이커(breakout), 네온 대시(runner), 하늘 탑 쌓기(tower), 오빗 점프(orbit), 네온 회피(dodge), 네온 블록(blocks)

살펴본 관점은 게임 로직과 플레이 경험입니다. 그래픽 대개편과 사운드 체계는 다른 스레드가 맡고 있어 여기서는 다루지 않았습니다. 이미 있는 `A.sfx` 이름을 부르거나 `fx` 효과를 더하는 정도만 했습니다.

공통으로 고친 것
- 매 프레임 `shadowBlur`를 쓰던 곳(runner 큐브, orbit 우주선, breakout 패들)을 미리 그린 그림으로 바꿨습니다. 테슬라 구형 칩에서 느려지는 원인입니다(지침 8장).
- `setTimeout`으로 탄을 예약하던 곳(dodge 나선, shooting 보스 연사)을 게임 시간 기준으로 바꿨습니다. 그래서 일시정지나 다시 하기를 해도 탄이 꼬이지 않습니다.
- 키보드 게임(shooting, breakout, dodge)은 창을 벗어날 때 눌린 키를 지웁니다. 전에는 돌아왔을 때 기체나 패들이 혼자 움직였습니다.
- 점수 체계가 바뀐 게임이 있지만, 8개 게임 모두 catalog의 maxScore(1천만)에 한참 못 미칩니다.

## 1. 별빛 수호대 (shooting)

**현재 상태**: 완성도가 높은 종스크롤 슈팅입니다. 웨이브 자동 생성, 보스, 콤보가 있습니다. 다만 작은 규칙 구멍과 타이머 꼬임이 있었습니다.

| 분류 | 우선 | 내용 |
|---|---|---|
| 버그 | 상 | 보스의 부채꼴 연사가 `setTimeout`이라 일시정지 중에 탄이 사라지거나 엇박자가 남 |
| 버그 | 중 | 목숨이 5개일 때 하트를 먹으면 '1UP' 글자만 뜨고 아무 효과가 없음 |
| 버그 | 중 | 창을 벗어났다 돌아오면 눌렸던 키가 남아 기체가 혼자 움직임 |
| 난이도 | 중 | 맞으면 화력이 1 줄어드는데 P 아이템이 나올 확률은 5%뿐이라, 한두 번 맞으면 만회가 어려움 |
| 재미 | 중 | '안 맞고 버티기'를 보상하는 장치가 없음 |
| 성능 | 하 | 매 프레임 적 출현 목록을 정렬함 |
| 안내 | 하 | 종료 화면의 '최대 화력'은 죽을 때 화력이라 '최대'가 아님 |

**이번에 고친 것**
- 보스 연사를 게임 시간으로 처리합니다(`e.salvo`). 일시정지하면 연사도 같이 멈춥니다.
- 목숨이 가득 찼을 때 하트를 먹으면 1000점을 줍니다.
- NO DAMAGE 보너스를 넣었습니다. 한 번도 안 맞고(보호막 피격 포함) 웨이브를 넘기면 웨이브×300점이고, 종료 화면에 '무피격 웨이브' 수가 나옵니다. 오해를 부르던 '최대 화력' 칸은 이것으로 바꿨습니다.
- 3웨이브부터 화력이 2 이하이면 아이템 확률이 +3%p 오릅니다.
- 창을 벗어나면 키를 초기화합니다. 출현 목록은 웨이브 시작 때 한 번만 정렬합니다.
- 아이템 설명에 '최대 5'와 무피격 보너스 줄을 넣었습니다.

**남은 제안**
- 보스 처치 연출의 연쇄 폭발도 `setTimeout`입니다. 그림만 그리는 것이라 그대로 두었습니다. → 그래픽 스레드 몫
- 폭탄(위기 탈출) 같은 능동 기술은 조작 체계가 바뀌는 일이라 하지 않았습니다.
- 10웨이브 이후에는 적 체력만 오르고 새 패턴이 없습니다. 새 적 종류나 보스 패턴은 다음 작업으로 제안합니다.

## 2. 네온 스네이크 (snake)

**현재 상태**: 벽을 통과하는 칸 기반 스네이크입니다. 보간과 입력 큐가 잘 되어 있습니다. 바위 배치가 불공정할 때가 있었고, 판이 거의 차면 먹이가 사라질 수 있었습니다.

| 분류 | 우선 | 내용 |
|---|---|---|
| 난이도 | 상 | 레벨업 바위가 '머리에서 6칸 이상'만 지키고 진행 방향은 보지 않음. 빠를 때 코앞 줄에 생기면 피할 시간이 0.3초 남짓 |
| 버그 | 중 | 무작위로 500번 찾아도 빈칸이 없으면 먹이가 `null`로 영영 사라져 진행이 막힘(판이 거의 찼을 때) |
| 안내 | 중 | '황금 먹이는 5배 점수'라고 쓰여 있지만 실제로는 남은 시간에 따라 5~11배 |
| 재미 | 중 | 먹이를 먹는 경로에 기술이 개입할 여지가 없음(빙 돌아가도 점수가 같음) |

**이번에 고친 것**
- 바위는 머리가 가는 줄의 앞 9칸(벽 통과 포함, 줄 서 있는 다음 방향 기준)과 먹이 바로 옆에는 생기지 않습니다.
- 빈칸을 무작위로 못 찾으면 판 전체를 훑어 고릅니다. 다음 걸음에 먹이가 없으면 다시 만듭니다.
- '빠르게!' 보너스를 넣었습니다. 먹이가 생긴 뒤 최단거리+4걸음 안에 먹으면 점수가 2배입니다. 종료 화면에 '빠르게 먹기 n/전체'가 나옵니다.
- 안내 문구를 실제 계산과 맞게 고쳤습니다.

**남은 제안**
- 레벨 9 이후로는 속도가 더 오르지 않고 바위만 최대 16개까지 늘어납니다. 후반에 '움직이는 먹이'나 '시간 제한 구역'을 두는 방안을 제안합니다.
- 머리 색으로 보너스 시간을 보여 주는 것 같은 표시 강화는 그래픽 스레드 몫입니다.

## 3. 네온 브레이커 (breakout)

**현재 상태**: 글자 지도 레벨 8개에 HARD MODE 반복, 아이템 5종이 있습니다. 강철 벽돌 사이에 공이 갇히거나 마지막 몇 개가 지루하게 남는 문제가 있었습니다.

| 분류 | 우선 | 내용 |
|---|---|---|
| 버그(막힘) | 상 | 강철 줄(예: 2·6·7스테이지)과 위 벽 사이에서 공이 거의 수직으로 끝없이 왕복할 수 있음. 수평 보정만 있고 수직 보정은 없음 |
| 재미 | 중 | 남은 벽돌이 1~2개일 때 맞히기까지 오래 걸려 지루함 |
| 성능 | 중 | 패들을 그릴 때 매 프레임 `shadowBlur = 20`(테슬라에서 느림) |
| 버그 | 중 | 창을 벗어났다 오면 눌린 키가 남아 패들이 혼자 움직임 |

**이번에 고친 것**
- 막힘을 방지합니다. 공이 7초 넘게 패들이나 벽돌에 못 닿으면 벽·천장·강철에 튕길 때마다 각도를 ±0.35rad 흔들어 왕복에서 빠져나오게 합니다.
- 벽돌이 25초 동안 하나도 안 깨지면 화면 위에서 불꽃공(F) 지원 아이템이 떨어집니다. 문구는 '지원 도착!'입니다.
- 패들의 빛 번짐은 미리 그린 빛 점을 늘려 겹치는 방식으로 바꿨습니다.
- 창을 벗어나면 키를 초기화합니다.

**남은 제안**
- 9스테이지부터는 같은 지도에 내구도만 +1입니다. 새 지도를 더 만들거나 무작위 지도를 생성하는 방안을 제안합니다.
- 공이 하나 남았을 때 슬로 모션 같은 연출은 그래픽 스레드 몫입니다.

## 4. 네온 대시 (runner)

**현재 상태**: 원탭 러너이고 지형 생성이 공정합니다. 다만 구덩이 판정 버그가 있었고, 손맛(점프 입력 여유)이 부족했습니다.

| 분류 | 우선 | 내용 |
|---|---|---|
| 버그 | 상 | 구덩이 아래로 빠지는 도중에 구덩이가 지나가면 땅 위로 순간이동해 다시 달림(좁은 구덩이에서 자주 일어남) |
| 조작 | 상 | 발판 끝에서 살짝 늦게 누르거나 착지 직전에 누르면 점프가 무시되어 '눌렀는데 안 뜀' |
| 재미 | 중 | 코인이 10점으로 고정이고, 위험을 감수한 보상이 없음 |
| 재미 | 하 | 목표감을 주는 중간 이정표가 없음 |
| 성능 | 중 | 큐브를 그릴 때 매 프레임 `shadowBlur` |
| 정리 | 하 | 쓰지 않는 변수 `keyHeld` |

**이번에 고친 것**
- 바닥선 아래로 내려간 뒤에는 땅으로 판정하지 않습니다. 구덩이에 빠지면 G+200에서 바로 끝납니다(전에는 화면 밖까지 기다림).
- 코요테 타임 0.09초와 점프 버퍼 0.13초를 넣었습니다. 이단 점프까지 쓴 뒤 착지 직전에 누르면 착지하자마자 뜁니다.
- 코인 연속 줍기 배율을 넣었습니다. 0.7초 안에 계속 주우면 4개마다 배율이 1씩 올라 최대 ×5이고, 위쪽 점수판에 'COIN ×n'이 뜹니다.
- 아슬아슬 보너스를 넣었습니다. 가시나 톱날을 24px 이내로 스치듯 넘으면 +20점이고, 종료 화면에 횟수가 나옵니다.
- 500m마다 배너가 뜹니다. 큐브는 스프라이트로 바꿨습니다. 설명 문구(json)도 새 규칙에 맞게 고쳤습니다.

**남은 제안**
- 블록 바로 뒤 40px 위치에 가시가 붙는 조합은 블록 위에서 미리 뛰어야 합니다. 보이니까 불공정하지는 않지만, 처음 보는 사람에게는 어렵습니다. 가시를 더 멀리 두는 방안을 검토하세요.
- 속도 상한(820)에 70초 만에 닿고, 그 뒤로는 새 장애물이 없습니다. 후반 전용 조각(움직이는 톱날 등)을 제안합니다.

## 5. 하늘 탑 쌓기 (tower)

**현재 상태**: 타이밍 쌓기 게임이고 연출이 좋습니다. 그런데 점수판과 최종 점수가 달라 혼란스러웠습니다.

| 분류 | 우선 | 내용 |
|---|---|---|
| 안내(버그) | 상 | 위쪽 첫 칸은 '층수'인데 끝나면 '층×10+완벽×5'가 나와 숫자가 갑자기 바뀜 |
| 난이도 | 중 | 완벽 판정 폭이 7px로 고정이라, 빨라지면(최대 560px/s, 한 프레임에 9~18px 이동) 운에 가까워짐 |
| 재미 | 중 | 완벽 콤보를 길게 이어도 보너스가 5점으로 고정 |
| 재미 | 하 | 아깝게 빗나간 것과 크게 빗나간 것의 차이가 없음 |

**이번에 고친 것**
- 점수판을 SCORE / FLOOR / COMBO로 바꾸고 실시간 점수를 보여 줍니다.
- 완벽 판정 폭을 속도에 비례시켰습니다(7 + 속도/140, 최대 약 11px).
- 콤보 보너스는 5×콤보입니다(최대 50). 글자에 얻은 점수를 같이 표시합니다.
- 판정 폭의 2.2배 안이면 'GOOD +13'(+3 보너스)을 줍니다. 블록 폭이 40px 아래로 줄면 '조심!' 문구가 뜹니다.
- 설명 문구(json)를 새 점수 규칙에 맞게 고쳤습니다.

**남은 제안**
- 30층 이후로는 변화가 속도뿐입니다. 바람(블록이 흔들림)이나 좁은 블록 구간 같은 단계 변화를 제안합니다.
- 층마다 배경이 바뀌는 연출 강화는 그래픽 스레드 몫입니다.

## 6. 오빗 점프 (orbit)

**현재 상태**: 원탭 궤도 점프입니다. 처음 하는 사람은 언제 눌러야 하는지 감을 잡기 어려웠고, 화면 밖에 갇히는 버그가 있었습니다.

| 분류 | 우선 | 내용 |
|---|---|---|
| 버그 | 상 | 카메라가 위로만 움직여서, 아래(지나온) 행성에 붙잡히면 우주선이 화면 밖에서 안 보인 채로 돎 |
| 안내 | 상 | 짧은 흰 점선만 있어서 '지금 쏘면 닿는지' 알 수 없음. 시작 3초 안에 할 일을 알기 어려움 |
| 재미 | 중 | 멀리 있는 행성으로 바로 가는 과감한 플레이에 보상이 없음 |
| 버그 | 하 | 행성을 건너뛰면 10행성 배너를 건너뛸 수 있음(나머지 계산) |
| 성능 | 중 | 우주선을 그릴 때 매 프레임 `shadowBlur` |

**이번에 고친 것**
- 카메라가 지금 행성을 따라 내려가기도 합니다. 최고 높이는 따로 기록합니다.
- 조준 도우미를 넣었습니다. 지금 쏘면 직선으로 날아가 위쪽 행성 궤도에 닿을 때 조준선이 노랗게, 목표까지 길어지고 목표 궤도에 원을 그립니다. 설명 문구도 '조준선이 노랗게 빛날 때 탭'으로 바꿨습니다.
- 건너뛰기 보너스를 넣었습니다. 사이에 있던 행성 하나마다 +150점이고 행성 수에도 더합니다. 종료 화면에 건너뛴 수가 나옵니다.
- 10행성 배너는 10의 자리가 바뀔 때 뜹니다. 우주선은 스프라이트로 바꿨습니다.
- 확인: 조준에 맞춰 쏘는 봇이 연속으로 실패 없이 진행했습니다(행성 18개, 건너뛰기 6회).

**남은 제안**
- 조준 도우미가 후반 난이도를 낮춥니다. 반응이 너무 쉽다는 의견이 나오면 30행성 이후에는 원만 보이고 선은 짧게 하는 방안을 쓰세요.
- 소행성을 고려한 조준(선이 소행성 띠를 지나면 빨갛게)은 다음 작업으로 제안합니다.

## 7. 네온 회피 (dodge)

**현재 상태**: 패턴 감독이 있는 생존 게임이고 레이저 경고가 공정합니다. 그런데 타이머가 꼬이고, 점수가 정수가 아닌 문제가 있었습니다.

| 분류 | 우선 | 내용 |
|---|---|---|
| 버그 | 상 | 나선 패턴이 `setTimeout`: 일시정지 중에 탄이 빠지고, 죽은 직후 바로 다시 하면 이전 판 탄이 새 판에 쏟아질 수 있음 |
| 버그 | 상 | 점수가 `시간×10` 소수라서 최고기록이 소수로 저장됨(규칙: 점수는 정수) |
| 조작 | 중 | 드래그하다 다른 자리를 빨리 다시 누르면 두 번 탭으로 인식되어 폭탄이 실수로 터짐 |
| 재미 | 중 | 피하기 실력(아슬아슬하게 피하기)에 보상이 없음 |
| 안내 | 하 | 레이저 경고가 눈으로만 보여서, 화면 밖을 보고 있으면 놓침 |
| 버그 | 중 | 창을 벗어나면 눌린 키가 남음 |

**이번에 고친 것**
- 나선을 게임 시간 예약 목록(`pend`)으로 바꿨습니다. 폭탄을 쓰면 남은 예약 탄도 지웁니다.
- 끝날 때 점수를 `Math.floor`로 정수로 만듭니다.
- 두 번 탭은 0.3초 안에 같은 자리(60px 이내)를 다시 누를 때만 인정합니다.
- 스침(그레이즈) 보너스를 넣었습니다. 탄이 판정선 밖 16px 안으로 지나가면 +10점입니다. 5번마다 글자가 뜨고, 종료 화면에 횟수가 나옵니다.
- 레이저 경고 때 `tick` 소리를 냅니다. 창을 벗어나면 키를 초기화합니다. 설명 문구(json)에 스침 규칙을 넣었습니다.

**남은 제안**
- 90초 뒤에는 패턴 간격이 0.55초 바닥에 머무릅니다. 2~3분대에 '휴식 구간'(10초 동안 약한 패턴)을 넣어 리듬을 주는 방안을 제안합니다.
- 탄 색으로 위험도를 구분하는 그래픽 개선은 그래픽 스레드 몫입니다.

## 8. 네온 블록 (blocks)

**현재 상태**: 8×8 블록 퍼즐로 기본은 탄탄합니다. 그런데 터치로 놓기가 까다로웠고, 운으로 끝나는 판이 있었습니다.

| 분류 | 우선 | 내용 |
|---|---|---|
| 조작 | 상 | 놓을 자리를 반올림 한 칸으로만 찾음. 손가락이 경계에서 조금만 어긋나도 옆 칸이 막혀 있으면 '안 놓임' |
| 난이도 | 상 | 새 조각 3개가 모두 들어갈 자리가 없게 뽑히면 바로 끝남(순전히 운) |
| 재미 | 중 | 콤보는 매번 놓을 때마다 줄을 지워야 이어져서 거의 못 쌓음 |
| 안내 | 하 | 끝날 때 왜 끝났는지 문구가 없음 |

**이번에 고친 것**
- 붙이기 도우미를 넣었습니다. 정확한 자리가 막혀 있으면 주변 3×3 가운데 0.8칸 안에서 가장 가까운 빈자리로 붙입니다.
- 공정하게 다시 뽑습니다. 새 3개 중 하나라도 놓을 수 있을 때까지 최대 25번 다시 뽑습니다.
- 콤보를 유지하는 여유를 줬습니다. 줄을 지운 뒤 3번 놓는 안에 또 지우면 콤보가 이어집니다.
- 끝날 때 '놓을 곳이 없어요' 문구와 화면 흔들림이 나옵니다. 설명 문구(json)를 고쳤습니다.

**남은 제안**
- 되돌리기 1회나 '조각 바꾸기' 아이템(일정 점수마다 1개)을 넣으면 오래 즐기기 좋습니다. 점수 체계와 균형에 영향을 주므로 다음 작업으로 미뤘습니다.
- 줄이 지워질 때 연출 강화는 그래픽 스레드 몫입니다.

## 가로 화면 (2단계)

가로 화면(휴대폰 가로, 테슬라, PC)에서는 540×960 세로형 판이 높이에 맞춰 아주 작아집니다. 판이 격자형인 게임만 가로 전용 배치(`land`, `onResize`)로 바꾸고, 나머지는 세로를 유지했습니다.

### 바꾼 게임

**네온 블록 (blocks)**: 가로에서는 820×600으로 그립니다. 8×8 판(칸 66)을 왼쪽에, 조각 3개를 오른쪽 세로 줄에 둡니다. 점수판(SCORE/LINES/COMBO)은 오른쪽 패널로 옮기고, 게임판 위 점수판은 가로에서 숨깁니다. 터치로 들 때 띄우는 높이는 가로에서 90으로 줄였습니다(세로는 120). 시작 설명의 '아래 조각' 문구도 방향과 상관없게 고쳤습니다.

**네온 스네이크 (snake)**: 가로에서는 600×660으로 그립니다. 판 위 60px 점수 여백을 없애고 점수·레벨·길이를 패널로 옮겼습니다. 칸 수(20×22)는 그대로 두었습니다. 칸 수를 가로형으로 바꾸면 화면을 돌릴 때 진행 중인 판을 유지할 수 없어서입니다. 그래서 커지는 정도는 약 9%로 작습니다.

| 게임 | 화면 | 전 판 크기(px) | 후 판 크기(px) |
|---|---|---|---|
| blocks | 휴대폰 가로 844×390 | 177×177 | 322×322 |
| blocks | 테슬라 1180×720 | 336×336 | 483×483 |
| blocks | PC 1440×900 | 423×423 | 623×623 |
| blocks | 휴대폰 세로 390×844 | 314×314 | 314×314 (그대로) |
| snake | 휴대폰 가로 844×390 | 305×335 | 332×366 |
| snake | 테슬라 1180×720 | 580×638 | 632×696 |
| snake | PC 1440×900 | 730×803 | 796×876 |
| snake | 휴대폰 세로 390×844 | 366×403 | 366×403 (그대로) |

(판 크기는 캔버스 실측값에 판이 차지하는 비율을 곱한 값입니다. snake는 점수 여백을 뺀 격자 부분입니다.)

확인한 것
- 위 4개 화면에서 스크린샷을 찍어 직접 봤습니다. 판과 패널이 겹치지 않았습니다.
- blocks: 휴대폰 가로에서 터치로 끌어 놓은 뒤 세로로 돌렸습니다. 판·조각·점수가 그대로였고 세로에서 다시 터치로 놓았습니다. 가로로 돌아와서도 유지되었고 패널 점수가 갱신되었습니다.
- snake: 세로에서 진행하다 가로로 돌렸습니다. 길이·점수·진행이 유지되었고, 패널 안 방향 패드로 방향이 바뀌었습니다.

남은 문제(엔진 몫): 휴대폰 가로(390 높이)에서 snake는 방향 패드가 패널에 들어가서, 일시정지 큰 버튼이 패널 아래로 밀려 스크롤해야 보입니다. P 키와 화면 밖 이탈 시 자동 일시정지는 됩니다. 패널 배치는 공통 엔진 담당(PR #29)에 넘깁니다.

### 세로 유지

| 게임 | 이유 |
|---|---|
| shooting | 적이 위에서 내려오고 피하는 세로 스크롤 슈팅이라, 세로 길이가 곧 반응 시간 |
| breakout | 공이 패들과 벽돌 사이를 위아래로 오가며, 세로 거리가 난이도의 핵심 |
| runner | 지형 생성 간격이 속도에 맞춰져 있고 하늘 배경·점프 높이가 세로 기준. 가로로 넓히면 앞이 너무 많이 보여 난이도가 바뀜 |
| tower | 블록이 위로 쌓이는 게임 |
| orbit | 행성을 따라 위로 올라가는 게임 |
| dodge | 판 크기 자체가 회피 공간이라 비율을 바꾸면 탄막 패턴의 공정성(레이저 위치·사방 탄)이 달라짐. 다음 작업으로 '가로 전용 패턴 재조정'을 함께 검토해야 함 |
