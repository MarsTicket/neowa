# 게임 보완 기획서 — 묶음 b (퍼즐·보드 6종)

대상: 지뢰 탐색(mines), 스도쿠(sudoku), 낙하 블록(fall), 바둑 묘수풀이(baduk), 네모 로직(nonogram), 솔리테어(solitaire)

점검 방법: 각 게임 코드를 끝까지 읽고, Playwright로 실제 상황(지뢰 연쇄 폭발, 바닥 회전 버티기, 터치 두 번 탭, 끌어 칠하기, 힌트만으로 끝까지 두기 등)을 재현해 확인했습니다. 고친 뒤 `smoke.js` 휴대폰·PC·테슬라 18개 화면 모두 통과.

---

## 1. 지뢰 탐색 (mines)

**현재 상태:** 기본 규칙·깃발·화음(숫자 탭)은 잘 되어 있지만, 판이 운에 따라 "찍어야만 하는 판"이 자주 나왔고 지뢰를 여러 개 동시에 열 때 처리에 버그가 있었습니다.

| 분류 | 우선순위 | 내용 |
|---|---|---|
| 난이도 | 상 | 무작위 배치라 찍기(50:50)가 필요한 판이 많음. 직접 재 보니 어려움에서 논리만으로 풀리는 판은 **8.5%**, 보통 37%, 쉬움 59% |
| 버그 | 상 | 숫자 탭(화음)으로 지뢰 2개 이상을 한 번에 열면 패배 처리가 여러 번 실행됨 (폭발 연출·공개 예약이 겹침) |
| 버그 | 중 | 패배 연출(남은 지뢰 공개)을 `setTimeout`으로 예약해서, 일시정지 중에도 진행되고, 바로 다시 하기를 누르면 새 판에 폭발 효과가 튐 |
| 안내 | 중 | 패배 후 어떤 깃발이 틀렸는지 알 수 없음 |
| 안내 | 하 | 상단 SCORE 예상치가 0까지 내려가지만 실제 승리 점수는 기본점 아래로 안 내려감 (표시와 실제가 다름) |
| 화면 | 하 | 가로 화면(테슬라·PC)에서 세로형 판이 작게 보임 → 사이트 UI 스레드 몫 |

**이번에 고친 것**
- **찍기 없는 판**: 첫 탭 뒤 지뢰를 놓을 때, 간단한 논리 풀이기(숫자 1개 규칙 + 숫자 2개 비교 + 남은 지뢰 수)로 끝까지 풀리는지 확인하고, 안 풀리면 다시 배치(최대 0.12초). 세 난이도 모두 실측 100% 논리로 풀림. 첫 탭 지연은 1~2ms 수준.
- 이미 졌거나 이긴 뒤에는 칸이 더 열리지 않게 막아서 패배 처리가 한 번만 됨.
- 지뢰 공개 연출을 게임 시간표(`reveals`)로 바꿔 일시정지·다시 하기와 엮이지 않게 함. 지뢰가 많으면 간격을 줄여 1.8초 안에 다 보이게.
- 패배 시 잘못 꽂은 깃발에 노란 X.
- 상단 점수 예상치 최소값을 승리 기본점으로 맞춤.
- 시작 설명에 "찍지 않아도 풀리는 판만 나와요" 추가.

**남은 제안**
- 가로 화면 전용 판 배치(`land` 해상도) — 사이트 화면 스레드와 맞춰야 해서 보류.
- 칸이 열릴 때 소리 높낮이 변화, 연쇄 열림 효과음 — 사운드 스레드 몫.

## 2. 스도쿠 (sudoku)

**현재 상태:** 매판 답이 하나뿐인 퍼즐을 빠르게(평균 3~9ms) 만들고 단서 수도 목표(40/32/26)에 정확히 맞습니다. 입력 처리에 작은 버그 두 개.

| 분류 | 우선순위 | 내용 |
|---|---|---|
| 버그 | 상 | 이미 틀린 숫자가 있는 칸에 같은 숫자를 다시 누르면 실수가 또 올라감 (손가락이 두 번 닿기만 해도 목숨이 깎임) |
| 버그 | 중 | 틀린 숫자가 있는 칸에 메모를 적으면 메모가 저장은 되는데 화면에 안 보임 |
| 재미 | 중 | 되돌리기 없음, 메모 자동 채우기 없음 (휴대폰에서 어려움 난이도 메모가 번거로움) |
| 난이도 | 하 | 난이도를 단서 수로만 나눔 (풀이 기법 난도는 따지지 않음) |

**이번에 고친 것**
- 같은 오답을 다시 누르면 "막힘" 소리만 나고 실수로 세지 않음.
- 메모 모드에서 틀린 숫자가 있는 칸을 누르면 틀린 숫자를 지우고 메모를 적음.

**남은 제안**
- 되돌리기·메모 자동 채우기 버튼: 도구 줄(지우기·메모·힌트) 배치를 바꿔야 해서 화면 스레드와 함께 하는 것이 좋음.
- 풀이 기법 기준 난이도(어려움은 숨은 싱글 이상 필요하게) — 생성 시간이 늘어 다음 기회에.

## 3. 낙하 블록 (fall)

**현재 상태:** 7종 가방 뽑기, 보관, 미리보기 3개, 고스트, 벽 차기, 콤보·4줄 연속 보너스·올 클리어까지 갖춘 완성도 높은 게임. 고정 대기 처리에 허점이 있었습니다.

| 분류 | 우선순위 | 내용 |
|---|---|---|
| 버그 | 상 | 바닥에서 회전이 위로 한 칸 튕기는 벽 차기([0,-1])가 되면 "공중"이 되어 고정 대기가 0으로 초기화되고 횟수에도 안 셈 → 회전만 계속 누르면 **블록이 영원히 안 놓임** |
| 조작 | 중 | 키보드 좌우를 같이 누르다 하나를 떼면 남은 쪽 키를 누르고 있어도 멈춤 |
| 안내 | 하 | 판 왼쪽 1/3을 탭하면 반대 방향으로 도는데 안내에 없음 |

**이번에 고친 것**
- 위로 튕긴 회전도 고정 대기 횟수(15번)에 셈. 15번을 다 쓰면 공중에 떠도 대기 시간이 초기화되지 않아 곧 놓임. 블록이 **더 아래 줄로 내려갔을 때만** 횟수를 다시 채움(표준 방식). 재현 테스트에서 고친 뒤 정상 고정 확인.
- 좌우 키를 둘 다 누르다 하나를 떼면 남은 방향으로 이어서 이동.
- 터치 안내에 "판 왼쪽 탭은 반대로" 추가.

**남은 제안**
- 시작 레벨 선택(고수용 5·10레벨 시작) — 시작 화면 버튼이 필요해 화면 스레드와 함께.
- 줄 지울 때 레벨별 효과음 변화 — 사운드 스레드 몫.

## 4. 바둑 묘수풀이 (baduk)

**현재 상태:** 문제은행 440개(2수 200, 3수 200, 4수 40)를 8방향 회전·뒤집기로 섞어 냅니다. 은행의 모든 수순을 따로 다시 두어 확인했고(합법 수인지, 마지막 수에 정확히 잡히는지, 패 규칙) **오류 0개**라 재생성하지 않았습니다.

| 분류 | 우선순위 | 내용 |
|---|---|---|
| 조작 | 상 | 휴대폰에서 판 한 칸이 약 40px라 손가락이 돌을 가려 옆 칸을 누르기 쉬움. 한 번 잘못 누르면 바로 ♥ 하나 잃음 (불공정한 실패) |
| 안내 | 중 | 시작 화면 조작 안내가 "탭 돌 놓기"뿐 |
| 난이도 | 하 | 20문제 뒤로는 4수 문제(40개)가 반복되어 긴 판에서 같은 모양이 다시 나올 수 있음 (회전으로 어느 정도 가려짐) |

**이번에 고친 것**
- **터치는 두 번 탭으로 확정**: 첫 탭은 반투명 흑돌과 깜빡이는 테두리로 자리만 고르고, 같은 자리를 한 번 더 탭하면 둠. 다른 자리를 탭하면 고른 자리만 옮김. 위쪽 안내 줄과 가로 패널에 "한 번 더 탭하면 둡니다" 표시. 마우스·키보드는 지금처럼 바로 둠.
- 시작 화면 칩·조작 안내를 실제 동작에 맞게 고침(터치/키보드 따로).

**남은 제안**
- 4수 문제 추가 생성(`node docs/tools/baduk_problems.js 0 0 80`, 한 문제 1~2분) — 시간이 오래 걸려 이번엔 보류.
- 정답 수순 재생 중 "다시 보기" 버튼.

## 5. 네모 로직 (nonogram)

**현재 상태:** 줄 풀이 알고리즘으로 논리만으로 풀리는 판을 고르는 좋은 구조. 다만 끌어 칠하기가 너무 관대해 한 번의 손짓으로 게임이 끝날 수 있었고, 막혔을 때 도움 장치가 없었습니다.

| 분류 | 우선순위 | 내용 |
|---|---|---|
| 버그 | 상 | 끌어서 칠하다 빈칸 여러 개를 지나가면 실수가 한꺼번에 3번 → 한 손짓에 즉시 패배. 대각선으로 끌면 엉뚱한 칸까지 칠해짐 |
| 규칙 | 중 | 80번 만들어도 논리로 안 풀리는 판이 나오면 그 판을 그대로 씀 → 찍어야 하는 판이 나올 수 있음(드묾) |
| 재미 | 중 | 힌트가 없어 막히면 실수 위험을 감수하고 찍어야 함 |
| 점수 | 중 | 승리 최소 점수(50)가 패배 점수(최대 600)보다 낮을 수 있음 |

**이번에 고친 것**
- **끌어 칠하기**: 처음 움직인 방향(가로/세로) 한 줄로만 칠하고, 실수가 한 번 나면 그 손짓은 멈춤.
- **힌트 3번**(아래 버튼·H 키): 지금 상태에서 줄 풀이로 확실한 칸 하나를 대신 채움. 1번에 10% 감점. 아래 버튼을 칠하기 / ✕ 빈칸 / 힌트 3개로 정리.
- 논리로 안 풀리는 판이 나오면 막히는 칸을 하나씩 미리 열어 줘서 반드시 논리로 풀리게 (안전장치. 실측 90판 모두 미리 연 칸 없이 풀림).
- 승리 최소 점수를 기본점의 절반으로 올려 패배 점수보다 항상 높게.

**남은 제안**
- 칠한 칸에 그림 색을 입혀 완성 때 "그림" 느낌 주기 — 그래픽 스레드 몫.
- 되돌리기(지금은 실수 즉시 확정이라 덜 필요).

## 6. 솔리테어 (solitaire)

**현재 상태:** 탭 자동 이동·드래그·되돌리기·자동 완성까지 잘 돼 있음. 막혔을 때 알려 주는 장치가 없고 끝내기 버튼이 위험했습니다.

| 분류 | 우선순위 | 내용 |
|---|---|---|
| 조작 | 상 | "끝내기" 버튼을 한 번만 스쳐도 바로 게임 종료 (되돌리기 바로 옆이 아니어도 아래 줄이라 잘 눌림) |
| 재미 | 상 | 힌트·막힘 안내가 없어, 더 둘 수가 없는데도 덱만 계속 넘기게 됨 |
| 버그 | 중 | 탭 자동 이동이 맨 아래가 K인 줄을 다른 빈 칸으로 옮기는 헛수를 함 (이동 수만 늘어남) |
| 키보드 | 하 | 키보드만으로는 특정 칸을 골라 옮기기 어려움 (1~7 키는 자동 이동만) |

**이번에 고친 것**
- **힌트 버튼**(가운데, H 키): 바닥 → 모으기 > 뒤집힌 카드 드러내기 > 넘긴 카드 → 바닥 > 덱 넘기기 순으로 쓸모 있는 수를 찾아, 옮길 카드(분홍)와 놓을 곳(노랑)을 깜빡임. 덱까지 다 봐도 둘 곳이 없으면 "더 옮길 카드가 없어요" 배너. 힌트만 따라 40판을 자동으로 둬 보니 무한 반복 0판, 12판 승리, 28판 막힘 안내 정상.
- **끝내기 확인**: 한 번 누르면 빨간 "정말 끝내기?"로 바뀌고 2.5초 안에 한 번 더 눌러야 끝남.
- 탭 자동 이동에서 K 줄을 빈 칸끼리 옮기는 헛수 제거.

**남은 제안**
- 키보드 전용 선택 커서(방향키로 카드 고르고 Space로 옮기기) — 조작 체계를 바꾸는 일이라 다음 기회에.
- 3장 넘기기 모드(고수용).

## 공통 메모
- 저장 키·점수 체계는 바꾸지 않았습니다(네모 로직 승리 최소점만 상향, 최대 6,000점으로 catalog maxScore 100,000 이내).
- 그래픽·사운드 체계는 건드리지 않았고, 기존 `A.sfx` 이름과 `fx` 효과만 썼습니다.

## 가로 화면 (2단계)

**문제:** 540×960 세로형 판은 가로 화면(휴대폰 가로 844×390, 테슬라 1180×720, PC 1440×900)에서 높이에 맞춰 줄어 아주 작아졌습니다(휴대폰 가로에서 판 폭 약 200px).

**방법:** 오목(`gomoku.js`)과 같은 방식. Shell에 `land: [가로 논리 해상도]`, `onResize`에서 판 위치·칸 크기를 다시 계산하고, 캔버스 아래쪽 버튼은 오른쪽 패널의 큰 버튼(`gp-btn`)으로 옮겼습니다. 판을 가리는 게임판 위 점수판은 가로에서 숨기고(`data-land-hide`) 패널 점수판이나 판 옆 빈 곳에 표시합니다. 세로 화면 배치는 그대로입니다.

| 게임 | 가로 논리 해상도 | 가로 배치 | 패널로 옮긴 것 |
|---|---|---|---|
| 지뢰 탐색 | 900×640 | 판을 눕혀 그림(가로 = 세로줄 수). 데이터는 그대로, 방향키도 화면 방향대로 | 깃발 모드 큰 버튼, 점수·시간·남은 지뢰 |
| 스도쿠 | 920×600 | 판 왼쪽, 오른쪽에 큰 3×3 숫자 버튼과 지우기·메모·힌트 | 점수·시간·실수 |
| 네모 로직 | 720×720 | 단서 포함 정사각형 판이 꽉 참 | 칠하기↔빈칸 전환 큰 버튼, 힌트, 점수·실수·시간 |
| 솔리테어 | 960×640 | 왼쪽: 덱·넘긴 카드·점수, 가운데: 바닥 7줄(긴 줄은 간격 자동 축소), 오른쪽: 모으기 4칸 | 되돌리기, 힌트, 끝내기(두 번 눌러 확인) |
| 바둑 묘수풀이 | 720×820 (원래 지원) | 확인만 함. 판 크고 패널 힌트 버튼 정상 | (원래 있음) |
| 낙하 블록 | **세로 유지** | 블록이 위에서 아래로 떨어져 쌓이는 게임이라 판(10×20)이 세로로 길어야 함. 가로로 바꿔도 판 높이가 화면 높이를 넘을 수 없어 이득이 없음 | – |

**전후 판 크기 (화면 픽셀, Playwright 실측)**
