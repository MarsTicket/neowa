# 게임 보완 기획서: 묶음 e

맡은 게임: 숫자 밀기(slide), 불 끄기(lights), 보석 매치(gems), 카드 짝 맞추기(memory), 빛 순서 기억(sequence), 파이프 연결(pipes), 버블 팡(bubbles), 색 채우기(flood), 타일 짝 잇기(pairs)

점검 방법: 고친 부분마다 Playwright 스크립트로 실제 상황을 만들어 확인했습니다. 예를 들면 "클리어 직후 일시정지 → 재개", "제한 횟수 초과 3번", "컴퓨터 풀이대로 6판 연속 풀기" 같은 상황입니다. 그다음 `smoke.js`를 휴대폰·PC·테슬라 화면에서 돌려 9개 게임 모두 통과했습니다.
분류: 버그 / 규칙 / 난이도 / 안내 / 재미 · 우선순위: 상 / 중 / 하

---

## 1. 숫자 밀기 `slide`
**현재 상태:** 퍼즐 자체는 잘 돌아갑니다. 다만 큰 판(4×4, 5×5)의 점수 계산이 지나치게 박해서, 몇 분만 걸려도 최저점이 나왔습니다.

| 분류 | 우선 | 내용 |
|---|---|---|
| 난이도 | 상 | 점수 식 `base×2 − 시간×base/120 − 이동×base/400` 때문에 5×5를 3분 넘게 풀면 거의 항상 최저점 50점. 4×4도 2분이면 바닥 |
| 안내 | 중 | 최단 시간(`neowa_slide_time_<난이도>`)을 저장만 하고 화면 어디에도 보여 주지 않음 |
| 재미 | 하 | 막혔을 때 쓸 힌트나 목표 그림 미리보기가 없음 |

**이번에 고친 것**
- 크기별로 기준 시간(25초, 90초, 240초)과 기준 이동 수(40, 140, 320)를 정했습니다. 보통 실력으로 풀면 기본 점수를 받고, 더 빠르고 적게 움직일수록 최대 4배까지 받습니다. 시험 결과 5×5를 3분 20초·300번 이동으로 풀면 3,378점입니다(예전 식은 50점). 최고점은 catalog의 maxScore 100,000 안에 들어옵니다.
- 점수판 작은 글씨에 `5×5 · 최단 3:20`을 표시합니다. 종료 화면에는 이동 수, 시간, 최단 시간(신기록이면 "신기록!")을 보여 줍니다.

**남은 제안**
- 목표 그림(정답 배치)을 길게 눌러 잠깐 보는 기능. 화면 UI가 늘어나는 일이라 다음으로 미뤘습니다.

## 2. 불 끄기 `lights`
**현재 상태:** 판은 항상 풀리지만 게임이 끝나는 조건이 없었습니다. 그래서 최고기록이 저장되지 않았습니다.

| 분류 | 우선 | 내용 |
|---|---|---|
| 버그 | 상 | `S.gameOver`를 부르는 곳이 없음. 단계를 끝없이 이어 갈 뿐이라 점수가 최고기록·랭킹에 남지 않음 |
| 재미 | 상 | "적게 누를수록 고득점"이라고 안내하지만 기준 횟수가 보이지 않아 목표가 없음 |
| 성능 | 중 | 켜진 칸마다 매 프레임 `shadowBlur 26` (지침 8장 위반, 7×7 판에서 테슬라가 느려짐) |
| 안내 | 하 | H(힌트) 키가 안내에 없음 |

**이번에 고친 것**
- 단계마다 **목표 횟수**를 둡니다(판을 만들 때 쓴 정답 누르기 수). **제한 횟수**는 목표×3+6입니다. 두 숫자는 판 위에 표시합니다.
- 제한 횟수를 넘기면 ♥ 하나를 잃고 같은 단계의 새 판이 나옵니다. ♥ 3개를 모두 잃으면 게임이 끝나고 기록이 저장됩니다.
- 목표 횟수 안에 풀면 **PERFECT** 보너스(50×단계)를 줍니다. 5단계마다 힌트가 1개 늘어납니다.
- 켜진 칸의 빛 번짐은 `A.sprite`로 미리 그려 두고 씁니다. 겉모습은 같습니다.
- json 안내 문구(규칙, 키)를 새 규칙에 맞췄습니다.

**남은 제안**
- 가우스 소거로 진짜 최소 횟수를 구해 목표로 쓰기. 지금 목표는 "판을 만든 횟수"라서 실제 최소보다 클 때가 있습니다. 그래서 화면 문구를 "최소"가 아니라 "목표"로 썼습니다.

## 3. 보석 매치 `gems`
**현재 상태:** 매치3 규칙과 특수 보석은 정상입니다. 다만 그리기 성능이 나빴고, 막혔을 때 도움이 없었습니다.

| 분류 | 우선 | 내용 |
|---|---|---|
| 성능 | 상 | 보석 64개를 매 프레임 `shadowBlur 10`으로 그림. 테슬라·저사양 휴대폰에서 끊김 |
| 안내 | 중 | 바꿀 곳을 못 찾으면 도움이 없음 (초보자가 멈춤) |
| 재미 | 중 | 이동 30번 고정이라 큰 연쇄를 만들어도 판이 더 길어지지 않음 |
| 조작 | 하 | 선택한 보석을 다시 눌러도 선택이 풀리지 않음 |
| 규칙 | 하 | 가로·세로가 겹친 L/T 모양이 일반 4개짜리와 같은 취급 (장르 관례로는 폭탄) |

**이번에 고친 것**
- 보석 모양을 색마다 스프라이트로 한 번만 그려 두고 씁니다. 화면 모습은 같습니다.
- 6초 동안 가만히 있으면 바꿀 수 있는 두 보석이 커졌다 작아지며 반짝입니다(힌트).
- 한 번의 이동에서 3연쇄가 나면 **이동 +1**을 줍니다.
- 선택한 보석을 다시 누르면 선택이 풀립니다. json 규칙 문구도 고쳤습니다.

**남은 제안**
- L/T 모양 특수 보석, 남은 특수 보석이 끝날 때 터지는 "보너스 타임". 규칙이 커지는 일이라 다음 단계로 미뤘습니다.
- 특수 보석의 모양 다듬기는 그래픽 담당 스레드 몫입니다.

## 4. 카드 짝 맞추기 `memory`
**현재 상태:** 기본 규칙은 좋습니다. 다만 일시정지할 때 판이 멈추는 버그가 있었습니다.

| 분류 | 우선 | 내용 |
|---|---|---|
| 버그 | 상 | 단계 클리어 뒤 `setTimeout(900ms)`으로 다음 판을 만듦. 그 사이 일시정지하면 다음 판이 영영 안 나옴. 시간만 흐르다 게임 오버 |
| 버그 | 중 | 다음 판으로 넘어가는 0.9초 동안에도 남은 시간이 줄어듦 |
| 조작 | 중 | 틀린 두 장이 덮일 때까지 0.7초를 기다려야 다음 카드를 뒤집을 수 있어 답답함 |
| 안내 | 하 | 콤보 배율이 점수판에 보이지 않음 |
| 버그 | 하 | 판 크기가 바뀌어도 키보드 커서 위치를 고치지 않음 |

**이번에 고친 것**
- 다음 판 넘기기를 update 안의 타이머(`nextT`)로 바꿨습니다. 일시정지 중에는 멈추고, 넘어가는 동안 시간이 줄지 않습니다.
- 틀린 두 장이 보이는 동안 다른 카드를 누르면 두 장을 바로 덮고 새 카드를 뒤집습니다.
- 점수판에 `콤보 ×n`을 표시하고, 판이 바뀔 때 커서 범위를 고칩니다.

**남은 제안**
- 판이 커질수록 "같은 그림 3장 중 2장 찾기" 같은 변형 단계를 넣기.

## 5. 빛 순서 기억 `sequence`
**현재 상태:** 규칙은 장르 그대로입니다. 다만 일시정지할 때 멈추는 버그가 있었고, 한 번만 틀려도 끝나서 너무 가혹했습니다.

| 분류 | 우선 | 내용 |
|---|---|---|
| 버그 | 상 | 단계 성공 뒤 `setTimeout(700ms)`으로 다음 단계를 시작함. 그 사이 일시정지하면 'wait' 상태에 영원히 머물러 진행할 수 없음 |
| 난이도 | 중 | 실수 한 번에 바로 끝. 긴 순서를 외운 노력이 손가락 실수 한 번에 사라짐 |
| 안내 | 중 | 칩 "10단계마다 속도 UP"과 실제(단계마다 조금씩 빨라짐)가 다름 |
| 재미 | 하 | 빠르게 따라 해도 얻는 것이 없음 |
| 성능 | 하 | 켜진 패드에 매 프레임 `shadowBlur 40` |

**이번에 고친 것**
- 대기를 update 타이머(`later()`)로 바꿨습니다. 성공 직후 일시정지 → 재개해도 정상 진행합니다(시험으로 확인).
- **실수 1번은 봐줍니다.** 같은 순서를 다시 보여 주고, 두 번째 실수에 끝납니다. 남은 기회는 화면 아래에 ♥로 보입니다.
- 3단계부터 한 칸당 평균 0.55초 안에 따라 누르면 "빠른 손!" 보너스를 줍니다.
- 켜진 패드의 빛은 `lighter`로 한 겹 더 그려 표현합니다(shadowBlur 대신). 안내 칩·규칙·설명을 실제 동작에 맞췄습니다.

**남은 제안**
- 패드 소리(음높이)를 더 또렷하게 바꾸는 일은 사운드 담당 스레드 몫입니다.

## 6. 파이프 연결 `pipes`
**현재 상태:** 판 생성(신장 트리)과 연결 판정은 정확합니다. 다만 한 판이 10분이라 너무 길었습니다.

| 분류 | 우선 | 내용 |
|---|---|---|
| 난이도 | 상 | 한 판 = 10분 고정. 지침의 "한 판 1~5분"을 크게 넘고, 중간에 긴장감이 없음 |
| 버그 | 중 | 점수판 `연결 n/전체`가 점수·단계·초가 바뀔 때만 갱신되어, 돌린 직후 최대 1초 늦게 바뀜 |
| 안내 | 중 | 어디가 끊겼는지 알기 어려워 큰 판(8×8, 9×9)에서 막힘 |
| 성능 | 중 | 물 닿은 파이프마다 매 프레임 `shadowBlur 12` (최대 81칸) |
| 기타 | 하 | 쓰이지 않는 변수 `fin` |

**이번에 고친 것**
- **남은 시간제**로 바꿨습니다. 2분으로 시작하고, 판을 풀 때마다 `15 + 칸 수×0.4`초를 더합니다(4×4 +21초, 9×9 +47초). 0초가 되면 TIME UP입니다.
- 점수판 갱신 조건에 연결 수를 넣어 바로 바뀌게 했습니다. 남은 시간이 15초 아래면 빨간색으로 보입니다.
- 물이 닿은 파이프 끝이 벽이나 안 맞는 칸을 향하면 **빨간 점**(물이 새는 곳)이 깜빡입니다.
- 빛 번짐은 반투명한 굵은 선을 한 번 더 그려 표현합니다. 쓰지 않는 코드도 지웠습니다.

**남은 제안**
- 길게 눌러 칸 잠그기(맞춘 칸 표시). 길게 누르기 판정을 새로 넣어야 해서 이번에는 뺐습니다.

## 7. 버블 팡 `bubbles`
**현재 상태:** 육각 격자, 낙하 판정, 벽 반사가 정상입니다. 다만 성능과 공정성에서 손볼 곳이 있었습니다.

| 분류 | 우선 | 내용 |
|---|---|---|
| 성능 | 상 | 버블 하나마다 매 프레임 `shadowBlur` + 원형 그라데이션을 새로 만듦(최대 100개 이상) |
| 규칙 | 중 | 터지지 않은 발사 뒤에는 떠 있는 버블 검사를 안 해, 드물게 허공에 붙은 버블이 남을 수 있음 |
| 공정성 | 중 | 조준선이 버블을 뚫고 지나가게 그려져, 실제 부딪히는 곳과 다르게 보임 |
| 안내 | 중 | 바닥선에 가까워져도 경고가 없음. '다음' 버블을 탭해 바꾸는 기능이 터치 안내에 없음 |
| 재미 | 하 | 연속으로 터뜨려도 보상이 없음 |

**이번에 고친 것**
- 버블 그림을 색마다 스프라이트로 한 번만 그려 둡니다. 겉모습은 같습니다.
- 착지할 때마다(터지지 않아도) 천장과 이어지지 않은 버블을 떨어뜨립니다. 시험 24~29발 동안 떠 있는 버블은 0개였습니다.
- 조준선은 실제 충돌 거리(R×1.75)에서 멈추고, 끝에 큰 점을 찍습니다.
- 맨 아래 줄이 바닥선 2줄 안으로 오면 선이 깜빡이고 "위험! 바닥선에 닿으면 끝"을 보여 줍니다.
- 연달아 터뜨리면 **콤보 배율**(×1.5, ×2 … 최대 ×3)을 줍니다. '다음 (탭=교체)' 표시를 넣고 규칙 문구도 고쳤습니다.

**남은 제안**
- 폭탄 버블·무지개 버블 같은 특수 버블. 규칙이 커지는 일이라 다음 단계로 미뤘습니다.

## 8. 색 채우기 `flood`
**현재 상태:** 판을 완전히 무작위로 만들어서, 제한 횟수 안에 풀 수 없는 판이 자주 나왔습니다.

| 분류 | 우선 | 내용 |
|---|---|---|
| 규칙 | 상 | 무작위 판이라 풀 수 있는지 보장이 없음. 2수 앞을 보는 풀이로 재 보니 쉬움(10×10/18번) 판의 약 16%가 18번 안에 안 풀림 |
| 안내 | 상 | 규칙 "연속 성공하면 단계 상승"인데 실제로는 아무것도 바뀌지 않음 |
| 재미 | 중 | 목표로 삼을 기준이 없음 |
| 성능 | 하 | 색 버튼 5개에 매 프레임 `shadowBlur` |

**이번에 고친 것**
- 판마다 컴퓨터 풀이(2수 앞을 보는 욕심쟁이 방식, 판 하나에 약 2~5ms)로 몇 번에 풀리는지 계산합니다. `기존 제한 − 2`번 안에 풀리는 판만 냅니다.
- 제한 횟수는 **컴퓨터 횟수 + 4**에서 시작합니다. 판을 풀 때마다 1씩 줄고, 컴퓨터 횟수 + 1에서 멈춥니다. 이렇게 "단계 상승"을 실제로 넣었고, 항상 풀 수 있습니다.
- 화면 아래에 "컴퓨터는 n번에 풀었어요"를 표시합니다. 같은 횟수 이하로 풀면 판 기본점만큼 보너스를 줍니다("컴퓨터 이김!", "동점!").
- 색 버튼의 빛은 반투명 테두리로 바꿨습니다. 시험으로 6판 연속 풀기와 제한 초과 게임오버를 확인했습니다.

**남은 제안**
- 판 모양 변형(구멍 있는 판, 2인 대결)은 다음 기획으로 미뤘습니다.

## 9. 타일 짝 잇기 `pairs`
**현재 상태:** 경로 판정(꺾임 2번, 바깥 테두리)과 자동 셔플은 정상입니다. 다만 콤보 규칙이 의미가 없었습니다.

| 분류 | 우선 | 내용 |
|---|---|---|
| 재미 | 상 | 콤보가 시간과 상관없이 실패 전까지 계속 쌓여, 사실상 늘 최대 배율(×5). 보상 장치가 의미 없음 |
| 버그 | 중 | 자동 셔플이 20번 시도 안에 짝을 못 만들면 짝 없는 판이 남아 시간만 흐를 수 있음 |
| 버그 | 하 | 판 크기가 바뀌어도 키보드 커서 범위를 고치지 않음 |
| 안내 | 하 | 콤보 배율이 보이지 않음 |

**이번에 고친 것**
- 콤보는 **3초 안에** 다음 짝을 지워야 이어집니다. 점수판에 `콤보 ×n`, 지울 때 "n 콤보 +점수" 글자가 뜹니다.
- 셔플 시도를 300번으로 늘렸습니다(판이 작아 금방 끝납니다).
- 단계가 바뀔 때 커서 범위를 고칩니다. 규칙 문구도 정리했습니다.

**남은 제안**
- 남은 시간이 적을 때 힌트 비용을 바꾸는 등 시간 밸런스 다듬기. 실제 사용자 기록을 본 뒤에 정하는 것이 좋겠습니다.

## 공통 메모
- 저장 키는 바꾸지 않았습니다. 점수는 모두 정수이고 클수록 좋습니다. 점수 식을 바꾼 slide·lights·bubbles·flood의 최고점은 모두 catalog maxScore 안에 들어옵니다.
- `arcade.js`, `arcade.css`, `catalog.json`, 메인, 생성기, smoke는 건드리지 않았습니다. 효과음은 기존 `A.sfx` 이름만 썼습니다.
- 그래픽 대개편(3D, 새 보석·버블 디자인)과 효과음·음악은 각 담당 스레드 몫입니다. 이번에는 겉모습이 같은 성능 개선(스프라이트 캐시)만 했습니다.
