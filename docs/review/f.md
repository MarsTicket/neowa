# 게임 보완 기획서 · 묶음 f

맡은 게임: 점과 상자(dots), 오목(gomoku), 리버시(reversi), 블랙잭(blackjack), 숫자 야구(baseball), 반응 속도(reaction), 암산 레이스(math), 색깔 함정(stroop), 에임 트레이너(aim), 다른 색 찾기(oddcolor), 숫자 순서 찾기(schulte)

점검 방법
- 보드게임 AI는 가짜 브라우저 환경에서 **새 AI와 옛 AI를 수십 판씩 맞붙여** 실력을 비교했습니다(흑백·선후 번갈아).
- 블랙잭 규칙(분할·피크·블랙잭 정산)은 카드 순서를 정해 두고 칩 계산을 하나하나 확인했고, 무작위 조작 2만 번으로 오류·음수 칩이 없는지 확인했습니다.
- 반응 속도·암산·스트룹은 시간을 흉내 내어 상황을 재현해 확인했습니다.
- 모든 게임을 키보드만으로, 둘이서 모드(dots·gomoku·reversi)는 터치·키보드로 실제 브라우저에서 끝까지 두어 보고 오류가 없는지 확인했습니다.

## 1. 점과 상자 (dots)
**현재 상태**: 규칙과 둘이서 모드는 정상. 다만 키보드 조작이 불편하고, 어려움 AI가 막판 전략(사슬 주도권)을 몰랐음.

| 분류 | 우선순위 | 내용 |
|---|---|---|
| 안내 | 상 | 방향키가 "남은 선 목록" 순서로 움직여서, 선을 하나 그을 때마다 커서가 엉뚱한 곳으로 튐. 위·아래 키도 좌우와 똑같이 동작 |
| 난이도 | 상 | 어려움 AI가 "마지막 2칸 양보(더블 딜)"를 몰라 긴 사슬 싸움에서 쉽게 짐 |
| 난이도 | 중 | 보통 AI는 안전한 선이 없을 때 아무 선이나 그어서 큰 사슬을 통째로 넘겨줌 |
| 재미 | 하 | 컴퓨터가 상자를 연달아 먹을 때 한 칸마다 0.45초씩 기다려 지루함 |
| 버그(성능) | 중 | 마지막 선 강조에 매 프레임 shadowBlur 사용(테슬라에서 느려질 수 있음, 지침 8장 위반) |

**이번에 고친 것**
- 키보드 커서를 **화면 방향대로** 가장 가까운 이웃 선으로 옮기게 바꿈. 이미 그은 선 위도 지나갈 수 있고, 커서 위치를 흰 원으로 표시. 둘이서 모드에서는 차례에 맞는 색으로 표시.
- 어려움 AI: 한 사슬만 열려 있고 끝 2칸이 남았을 때, 그 뒤에 3칸 이상 사슬이 남아 있으면 **2칸을 일부러 양보**해서 다음 긴 사슬의 주도권을 가져감.
- 보통 AI: 안전한 선이 없으면 60% 확률로 가장 작은 사슬을 내줌.
- 컴퓨터가 연속으로 상자를 먹을 때 대기 0.25초로 단축.
- shadowBlur 대신 굵은 반투명 선을 한 번 더 그려 강조.
- 결과: 새 어려움 AI가 옛 어려움 AI에게 5x5·6x6 판에서 각각 30:10, 29:11로 이김.

**남은 제안**
- 혼자 모드에서 판마다 선(먼저 두는 쪽)을 번갈아 주기 (지금은 항상 내가 먼저).
- 쉬움에서 "세 번째 변" 위험 선을 살짝 표시해 주는 초보 도움말.
- 상자 칠하기·선 긋기 애니메이션 고급화는 그래픽 담당 스레드 몫.

## 2. 오목 (gomoku)
**현재 상태**: 판·무르기·가로 화면 패널·둘이서 모드는 잘 동작. **AI가 띈 모양(X.XX, XX.XX)을 못 알아봐서** 사람이 띈 삼으로 쉽게 이김.

| 분류 | 우선순위 | 내용 |
|---|---|---|
| 난이도 | 상 | AI 점수 계산이 "붙어 있는 돌 개수"만 봐서 띈 삼·띈 사를 모르고, 쌍삼·사삼도 우연히만 잡음 |
| 난이도 | 상 | 어려움도 한 수 앞만 봄. 연속 넉(계속 4를 만들어 이기는 수)도, 상대의 연속 넉도 못 읽음 |
| 버그(성능) | 중 | 돌 169개를 매 프레임 shadowBlur로 그림 (지침 8장 위반, 테슬라에서 느려짐) |
| 버그(성능) | 하 | 승리 줄 강조도 매 프레임 shadowBlur |

**이번에 고친 것**
- AI 평가를 **9칸 모양 판정**으로 새로 만듦: 오목 / 열린 넉 / 넉(띈 넉 포함) / 열린 셋(띈 셋 포함) / 닫힌 셋 / 열린 둘. 사삼·쌍사·쌍삼은 따로 큰 점수.
- 순서: ① 바로 이기기 ② 상대 오목 막기(쉬움은 15% 놓침) ③ 연속 넉 승리(보통 4수, 어려움 10수) ④ 어려움: 상대에게 연속 넉 승리 길이 있으면 그 길을 끊는 수 ⑤ 어려움: 열린 셋·넉으로 몰아붙이는 연속 위협 ⑥ 공격+수비 점수 1등 수.
- 탐색은 **횟수와 시간(어려움 0.18초)** 둘 다 제한 → 느린 기기에서도 멈춤 없음.
- 돌 그림을 크기별 스프라이트로 미리 그려 shadowBlur 제거, 승리 줄도 반투명 굵은 선으로 대체.
- 결과: 새 어려움 AI vs 옛 어려움 AI 10판 → 6승 1패 3무 / 7승 0패. 새 보통도 옛 어려움에게 6승 0패.

**남은 제안**
- 흑(사람)이 먼저 두는 자유 오목이라 흑이 유리. 원하면 어려움에 "렌주 금수(흑 쌍삼 금지)" 옵션을 추가할 수 있음.
- 마지막 판에서 졌을 때 "한 수 무르고 이어 하기"(점수 감점) 기회.

## 3. 리버시 (reversi)
**현재 상태**: 규칙(뒤집기·패스·끝내기)과 둘이서 모드는 정확함. AI가 얕고, 연출에 작은 오류.

| 분류 | 우선순위 | 내용 |
|---|---|---|
| 난이도 | 상 | 보통은 한 수만, 어려움도 3수까지만 보고, 모서리를 이미 차지해도 옆 칸(X·C칸)을 계속 나쁘게 봄. 막판 돌 수 계산 없음 |
| 버그 | 중 | 새로 놓은 돌이 0.17초 동안 **반대 색**으로 보였다가 바뀜(뒤집기 연출이 새 돌에도 적용됨) |
| 안내 | 하 | 패스 안내가 "둘 곳이 없어 차례가 넘어갑니다"뿐이라 누가 넘겼는지 모름 |
| 버그(성능) | 중 | 돌 64개 매 프레임 shadowBlur |

**이번에 고친 것**
- **알파-베타 탐색** 도입. 보통 = 2수 앞(15%는 단순 수), 어려움 = 시간(0.35초) 안에서 깊이를 늘려 감 + **빈칸 12개 이하이면 끝까지 계산**해서 돌 수 차이 최대 수를 둠.
- 평가: 자리 점수 + 모서리를 차지하면 옆 칸 감점 취소 + 기동력(둘 수 있는 곳 수) + 막판엔 돌 수.
- 이동 생성을 빠르게 다시 씀(탐색 속도 향상).
- 새 돌은 톡 튀어나오는 연출로, 뒤집히는 돌만 뒤집기 연출.
- 패스 안내에 "나/컴퓨터(둘이서: 흑/백) 둘 곳 없음" 표시 + 소리.
- 그림자를 반투명 원으로 대체해 shadowBlur 제거.
- 결과: 새 어려움 vs 옛 어려움 8:2(평균 21개 차), 새 보통 vs 옛 보통 10:0, 새 어려움 vs 새 보통 8:2.

**남은 제안**
- 둘 곳 위에 "몇 개 뒤집히는지" 작은 숫자 미리보기(쉬움 전용) 추가.
- 리버시에도 무르기 기능.

## 4. 블랙잭 (blackjack)
**현재 상태**: 기본 진행은 되지만 **실제 블랙잭 규칙과 다른 점**이 여럿 있었음.

| 분류 | 우선순위 | 내용 |
|---|---|---|
| 규칙 | 상 | **분할(스플릿) 없음**: 같은 숫자 2장이 와도 나눌 수 없음 |
| 규칙 | 상 | 딜러가 A·10을 보여도 블랙잭 확인(피크)을 안 해서, 딜러 블랙잭인데 내가 더블까지 걸고 2배로 잃을 수 있음 |
| 규칙 | 중 | 내가 블랙잭이어도 딜러가 카드를 계속 받는 연출이 나옴 |
| 버그 | 중 | 베팅 −/+가 50씩이라 10 → 60 → 110처럼 어색한 값, 칩이 적을 때 조절이 불편 |
| 재미 | 하 | 연승 보상·마지막 판 알림 없음 |

**이번에 고친 것**
- **분할 추가**: 같은 값(10·J·Q·K 포함) 2장이면 `분할 X` 버튼/키. 두 손을 왼쪽·오른쪽으로 작게 나눠 보여 주고 지금 손을 금색으로 강조. 분할 후 더블 가능, A 분할은 한 장씩만, 분할 21은 블랙잭이 아닌 1배.
- **딜러 피크**: 딜러가 A·10을 보이면 바로 블랙잭 확인 → 딜러 블랙잭이면 즉시 정산(내 블랙잭이면 푸시).
- 내 블랙잭은 즉시 1.5배 정산. 모든 손이 버스트면 딜러는 더 받지 않음.
- 베팅 조절: 금액 크기에 맞춘 단계(10/50/100/500), `절반`·`올인` 버튼 추가.
- 3연승부터 "N연승!" 표시, 마지막 20번째 판 배너.
- 안내(json)에 X 분할 키와 규칙 추가.

**남은 제안**
- 보험(인슈어런스)·서렌더는 넣지 않음(초보에게 복잡). 필요하면 추가 가능.
- 이론상 올인 연승으로 칩이 catalog maxScore(1,000,000)를 넘을 수는 있으나 20판 안에서는 사실상 불가능(보고만 함).

## 5. 숫자 야구 (baseball)
**현재 상태**: 판정은 정확. 그러나 **기록이 8줄만 보여서** 9·10번째 시도 때 처음 기록이 사라져 추리가 어려웠음.

| 분류 | 우선순위 | 내용 |
|---|---|---|
| 버그 | 상 | 기록 10줄 중 최근 8줄만 표시 → 추리에 필요한 첫 기록이 가려짐 |
| 안내 | 중 | 처음 시작했을 때 빈 화면이라 무엇을 하는지 바로 안 보임 |
| 재미 | 중 | 메모 기능이 없어 머릿속으로 지운 숫자를 기억해야 함 |

**이번에 고친 것**
- 기록 10줄을 모두 보이도록 줄 간격 조정.
- 시작 직후 "숫자 N개를 고르고 확인을 누르세요 / 1S 1B 뜻" 안내 표시.
- OUT(0S 0B)이 나온 숫자는 숫자판에서 **흐리게+빗금** 표시(누를 수는 있음). 규칙 안내에도 추가.

**남은 제안**
- 길게 눌러 숫자를 직접 "메모(제외/확정)"하는 기능.

## 6. 반응 속도 (reaction)
**현재 상태**: 짧고 단순. **초록 화면에서 일시정지하면 기록이 망가지는 버그**가 있었음.

| 분류 | 우선순위 | 내용 |
|---|---|---|
| 버그 | 상 | 초록 화면 중 일시정지/다른 창 → 돌아와서 누르면 멈춘 시간까지 더해져 수천 ms 기록 |
| 버그 | 중 | 측정 시작이 화면이 실제로 초록으로 그려지기 전(업데이트 시점)이라 최대 한 프레임 손해 |
| 재미 | 중 | 기다렸다 누르기만 반복. 함정이 없어 리듬으로 찍어 누르기 쉬움 |

**이번에 고친 것**
- 초록 화면 중 0.4초 넘게 멈췄다 돌아오면 그 회차를 "다시 기다리기"로 되돌림(기록 안 남김).
- 측정 시작을 **초록 화면이 실제로 그려진 순간**으로 변경.
- 2회차부터 40% 확률로 **파란 속임수 화면**("참아요!") 등장, 누르면 +500ms. 안내 문구에 반영.

**남은 제안**
- 초록 화면에서 아무것도 안 누르면 무한 대기 → 2초 뒤 "놓쳤어요" 처리.
- 5회 → 난이도 선택(5/10회) 정도.

## 7. 암산 레이스 (math)
**현재 상태**: 입력과 자동 판정은 잘 됨. **실력 좋은 사람은 끝나지 않는 문제**와 음수 답 입력 문제.

| 분류 | 우선순위 | 내용 |
|---|---|---|
| 난이도 | 상 | 정답마다 +2초라 빠른 사람은 시간이 계속 늘어 끝나지 않음(99초 상한에 머묾) |
| 버그 | 중 | 답이 음수(-5)인데 5를 누르면 아무 반응 없이 멈춘 것처럼 보임(한 자리 더 쳐야 오답 처리) |
| 안내 | 중 | 규칙에 "연속 정답일수록 어려운 문제"라 적혔지만 실제로는 맞힌 문제 수 기준. Tab(건너뛰기) 키 안내 없음 |
| 재미 | 하 | 단계 변화가 곱셈 하나뿐, 목표 장치 없음 |

**이번에 고친 것**
- 정답 보너스 시간을 맞힌 수에 따라 2 → 1.5 → 1 → 0.7 → 0.5초로 줄임. 1초에 1문제를 푸는 완벽한 사람도 약 4분 뒤 끝남(점수 약 6.8만, maxScore 10만 이내).
- 10문제마다 "N문제!" 배너 + 3초 보너스(50문제까지).
- 20문제부터 **나눗셈**, 30문제부터 두 자리 × 한 자리 곱셈. 같은 문제 연속 방지.
- 부호가 틀리면 바로 오답 처리.
- 규칙·키 안내를 실제 동작에 맞게 수정(Tab 건너뛰기 추가).

**남은 제안**
- 난이도 선택(덧뺄셈만 / 사칙연산) 버튼.

## 8. 색깔 함정 (stroop)
**현재 상태**: 규칙은 맞지만 45초 동안 난이도 변화가 거의 없음.

| 분류 | 우선순위 | 내용 |
|---|---|---|
| 재미 | 중 | 같은 문제가 연달아 나올 수 있고, 함정 빈도가 처음부터 끝까지 같음 |
| 재미 | 중 | 버튼 위치가 고정이라 후반엔 손이 위치만 외워서 누름 |
| 재미 | 하 | 빠르게 맞혀도 보상 없음 |

**이번에 고친 것**
- 같은 (글자, 색) 연속 출제 방지. "뜻을 고르세요" 함정이 맞힐수록 잦아짐(12% → 최대 35%).
- **25개를 맞히면 버튼 자리가 매번 섞임**(배너로 알림). 키보드 1~4는 화면 위치 기준이라 계속 사용 가능.
- 1초 안에 맞히면 +5점 "빠름!".
- 규칙 안내 갱신.

**남은 제안**
- 색 이름 대신 모양·방향 등 다른 함정 유형.

---

## 9. 에임 트레이너 (aim)
**현재 상태**: 마우스·터치 전용이라 **키보드만으로는 플레이 불가**(사이트 원칙 위반). 과녁이 겹쳐 나올 수 있음.

| 분류 | 우선순위 | 내용 |
|---|---|---|
| 안내 | 상 | 키보드 조작이 아예 없음("마우스 필요") |
| 버그 | 중 | 새 과녁이 기존 과녁 위에 겹쳐 생김 |
| 재미 | 중 | 30초 내내 같은 과녁, 특별한 목표 없음 |

**이번에 고친 것**
- **키보드 조준점**: 방향키/WASD로 이동(오래 누르면 빨라짐), Space로 쏘기. 마우스·터치를 쓰면 조준점은 숨김.
- 과녁끼리 겹치지 않게 자리 선택.
- 12% 확률 **황금 과녁**(작고 빨리 사라짐, 3배 점수), 후반에는 좌우로 움직이는 과녁.
- 10연속 명중마다 축하 문구, 종료 화면에 최대 연속 기록.
- 키·규칙 안내 갱신.

**남은 제안**
- 30/60초 모드 선택.

---

## 10. 다른 색 찾기 (oddcolor)
**현재 상태**: 단계 진행은 좋음. **키보드 조작 없음**.

| 분류 | 우선순위 | 내용 |
|---|---|---|
| 안내 | 상 | 키보드만으로 플레이 불가 |
| 안내 | 하 | 설명에 "시간 안에 못 찾으면 시간이 줄어요"라고 되어 있으나 그런 규칙 없음 |
| 재미 | 중 | 빨리 찾아도 보상 없음 |

**이번에 고친 것**
- 방향키 커서(끝에서 반대쪽으로 넘어감) + Space 선택.
- 2초 안에 찾으면 1.5배 점수 + "빠름!" 표시.
- 설명·규칙·키 안내를 실제 동작에 맞게 수정.

**남은 제안**
- 시간이 다 됐을 때 정답 타일 강조에 shadowBlur를 쓰는데, 종료 직전 1초만이라 그대로 둠(그래픽 담당 정리 시 함께).

---

## 11. 숫자 순서 찾기 (schulte)
**현재 상태**: 규칙·키보드 입력 정상. 한 판이 짧고, 막히면 계속 헤맴.

| 분류 | 우선순위 | 내용 |
|---|---|---|
| 재미 | 중 | 다음 숫자를 오래 못 찾으면 도움 없이 시간만 흐름 |
| 버그 | 하 | 다시 하기 때 키보드 입력 버퍼가 남아 있을 수 있음 |

**이번에 고친 것**
- 6초 넘게 다음 숫자를 못 찾으면 그 칸 테두리가 은은하게 깜빡여 알려 줌.
- 다시 하기 때 키보드 입력 버퍼 초기화.

**남은 제안**
- "3판 연속 합계 시간" 모드, 숫자 대신 글자(가나다) 모드.

---

## 공통으로 확인한 것
- 저장 키·점수 체계(정수, 클수록 좋음)는 그대로. 엔진 예약 키(Space/Enter/P/Esc/M/F/R)는 원래 용도 유지(블랙잭 분할은 X 키).
- 구형 브라우저 금지 문법(`?.`, `??`, `Array.at`, `roundRect`, `ctx.filter`) 사용 안 함. 매 프레임 shadowBlur는 dots·gomoku·reversi에서 제거.
- 그래픽 고급화·효과음 체계 변경은 하지 않음(다른 스레드 몫).

---

## 가로 화면 (2단계)

**문제**: 세로형 540×960 판은 가로 화면에서 높이에 맞춰 줄어 아주 작아졌습니다(휴대폰 가로에서 폭 205px).

**방법**: 공통 엔진은 그대로 두고 게임마다 가로 전용 논리 해상도(`land`)와 `onResize`로 배치를 다시 계산합니다.
- 격자 판 게임(dots·reversi·schulte·oddcolor)은 **720×720 정사각형 판**(오목과 같은 방식).
- 버튼·숫자판이 게임의 일부인 게임(baseball·math·stroop·blackjack)은 **900×600 가로형**: 왼쪽에 문제·기록·카드, 오른쪽에 큰 숫자판/색 버튼/행동 버튼.
- aim은 900×600 가로형 사격장. 화면을 돌리면 과녁·조준점을 새 범위 안으로 옮깁니다.
- 모두 가로에서는 게임판 위 점수판을 숨기고(`data-land-hide`), **오른쪽 패널 점수판**(`g-card gp-stats`)에 같은 내용을 보여 줍니다(난이도 표시 포함). 시간제 게임(math·stroop·aim)은 남은 시간을 판 안에도 막대로 보여 줍니다.
- 진행 중 상태(판 내용, 입력 중 숫자, 타이머, 카드)는 회전해도 그대로입니다. 터치 판정은 그리기와 같은 배치 함수를 써서 항상 일치합니다.

**판(캔버스) 크기 비교 (CSS px, 너비×높이)**

| 게임 | 화면 | 전 | 후 |
|---|---|---|---|
| dots·reversi·schulte·oddcolor | 휴대폰 가로 844×390 | 205×366 | **366×366** |
| 〃 | 테슬라 1180×720 | 391×696 | **696×696** |
| 〃 | PC 1440×900 | 492×876 | **876×876** |
| baseball·math·stroop·blackjack·aim | 휴대폰 가로 844×390 | 205×366 | **522×348** |
| 〃 | 테슬라 1180×720 | 391×696 | **750×500** |
| 〃 | PC 1440×900 | 492×876 | **968×645** |
| 전부 | 휴대폰 세로 390×844 | 366×650 | 366×650 (변화 없음) |
| gomoku (확인만) | 휴대폰 가로 / 테슬라 / PC | 366 / 696 / 876 정사각형 | 그대로 정상 |

글자·버튼 크기로 보면 휴대폰 가로에서 정사각형 판은 약 1.8배, 가로형 판은 약 2.5배 커졌습니다(가로형은 같은 내용을 가로로 펼쳐서 버튼이 더 큼).

**점검**: 4개 화면(844×390 터치, 1180×720 터치, 1440×900, 390×844)에서 시작 → 판 터치로 진행 → 휴대폰 가로→세로→가로로 돌리기를 해 보고 스크린샷을 직접 확인. 회전 전후 점수판 값이 같고(시간제 게임은 흐른 시간만큼만 줄어듦) 오류 없음. 블랙잭 분할 화면도 가로에서 확인.

**세로 유지 / 남은 제안**
- reaction(화면 전체가 버튼)은 판 비율과 상관없이 어디를 눌러도 되므로 바꾸지 않았습니다. 가로에서 작아 보이지만 플레이에 지장 없음 → 필요하면 900×600으로 쉽게 바꿀 수 있음.
- 가로형 게임은 3:2 비율이라 테슬라·PC에서는 위아래 여백이 남습니다(휴대폰 가로를 우선). 테슬라 전용으로 더 정사각형에 가까운 배치를 따로 두면 더 커질 수 있음.
- dots·reversi의 차례 표시는 판 위 글자로 두었습니다. 오목처럼 패널 "차례 카드"로 옮기면 판을 조금 더 키울 수 있음.

## 3단계: 재미·재방문

블랙잭 점수 상한: 20판 뒤 최종 점수는 catalog maxScore(1,000,000)에서 잘라 기록합니다(화면의 칩 표시는 그대로).

| 게임 | 첫 플레이 안내 (`neowa_<id>_tut`) | 목표·단계감 | 재방문 (종료 화면·오늘의 도전) |
|---|---|---|---|
| dots | 첫 판에 "두 점 사이를 탭해서 선을 그어요"(키보드: 클릭 · 방향키 + Space)와 그을 자리 손가락 표시. 첫 선을 그으면 사라짐 | (기존 연승·배너로 충분) | 종료 화면에 "모은 상자" 합계 |
| reversi | 첫 판에 "초록 점 자리를 탭하면 돌을 놓아요"와 둘 수 있는 칸 표시. 첫 수를 두면 사라짐 | (기존) | 종료 화면에 난이도 |
| blackjack | 2단계 안내: 딜 버튼을 가리키며 "딜을 눌러 카드를 받아요" → 첫 판에 "더 받으려면 히트, 멈추려면 스탠드". 히트·스탠드를 누르면 끝 | 3연승부터 연승 표시, 마지막 판 배너(1단계) | 종료 화면에 최대 연승. 점수는 상한에서 자름 |
| aim | 첫 판에 "과녁이 작아지기 전에 탭!"(키보드: 과녁 클릭 · 방향키로 조준하고 Space)과 과녁 표시. 첫 명중에 사라짐 | 10연속 명중 축하(1단계) | (기존: 명중·정확도·최대 연속) |
| baseball | (기존 빈 화면 안내로 충분) | 연속 도전(기존) | **오늘의 도전**(3번째 버튼, 3자리, 오늘은 모두 같은 문제 순서), 종료 화면에 평균 시도 수 / 오늘 최고 |
| math | (화면이 곧 안내라 생략) | 10문제 배너(1단계) | **오늘의 도전**(새 모드 버튼), 종료 화면에 최대 콤보·정확도 / 오늘 최고 |
| stroop | (화면 안내 문구로 충분) | 25개 돌파 배너(1단계) | **오늘의 도전**, 종료 화면에 정답(정확도%)·최대 콤보·빠른 정답 수 / 오늘 최고 |
| oddcolor | (화면 안내 문구로 충분) | 단계·칸 증가(기존) | **오늘의 도전**, 종료 화면에 빠른 찾기 수(최고 연속)·마지막 색 차이 / 오늘 최고 |
| schulte | ("다음: 1" 표시로 충분) | 6초 힌트(1단계) | **오늘의 도전**(4번째 버튼, 5×5), 종료 화면에 "최단 대비 ±초" / 오늘 최고 |
| reaction, gomoku | 이미 화면에 할 일이 크게 나와 생략 | — | (기존 meta 3개 유지) |

오늘의 도전 방식
- 로컬 날짜(YYYYMMDD)로 시드를 정한 작은 난수(mulberry32)를 게임 안에 두고, **문제를 만드는 부분만** 이 난수를 씁니다(파티클 등은 그대로). 기본 모드는 이전처럼 매번 다름.
- 난이도 버튼 뒤쪽 인덱스로 붙여 기존 `neowa_<id>_diff` 의미는 그대로. math·stroop·oddcolor는 새로 `neowa_<id>_diff`(0 기본, 1 오늘의 도전)를 씀.
- 오늘 최고 점수는 `neowa_<id>_daily_<YYYYMMDD>`에 저장해 종료 화면에 보여 줌. 점수 체계는 기본 모드와 같아서 최고기록·랭킹에도 그대로 올라감.
- 점검: 같은 날 두 번 불러도 같은 문제 6개, 기본 모드는 매번 다름(5종 모두 확인). aim·reaction은 화면 크기·반응 시간에 따라 판이 달라져서 오늘의 도전을 넣지 않음.

사이트 공통 제안 (엔진 몫이라 이번엔 아이디어만)
- 메인 화면에 "오늘의 도전" 묶음 카드(두뇌 게임 5종의 오늘 점수를 한눈에, 모두 하면 배지).
- 오늘의 도전 점수만 따로 모으는 일일 랭킹.
- 사이트 공통 업적(예: 게임 10종 플레이, 3일 연속 접속)과 프로필 화면.
